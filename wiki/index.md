# Wiki Index

The catalog of all pages in this wiki. Each entry: a wikilink to the page and a one-line summary. The LLM reads this first when answering queries to identify candidate pages.

Keep summaries tight — one line each. The index is engineered to be cheap to read; a fat index defeats its purpose.

When this file exceeds ~300 lines or the wiki passes ~150 pages, shard into `wiki/indexes/<type>.md` and replace this file with a directory of shards. See the `scaling-playbook.md` reference in the `llm-wiki` skill for the migration procedure.

## Concepts

- [[account-resolution]] — `findAccount` is a direct-import DB resolver, not a config option; enforces active status at every resolution and merges claims from the user record.
- [[admin-audit-trail]] — audit-first *and* authorization-first, in that order and inside the handler; a load-bearing route table; field names never values, and only the names that actually changed; Elysia strips undeclared query params before validation; stored ids are never rewritten but read and filtered in today's words, with the removed Project entity shown as a retired project.
- [[admin-provisioning]] — the console's records are seeded by `db:setup`/`db:setup:pg`, never at boot; the values are declared once in `admin_seed.ts` so a change cannot land in the seeder production never runs; re-run after an upgrade.
- [[per-issuer-isolation]] — declared resources are unique per issuer and each addressable project signs with keys of its own; the root namespace is super-admin only because metadata cannot name a root tenant; the no-transition key switch and the 30 s TTL rotation is built on.
- [[team-ownership]] — a team (stored as an administrator group) owns every project (and through it the project's applications and APIs) and is the only thing that grants access; owner-vs-member is a property of a membership, not a role; the active scope lives on the session and is re-validated per request; a refusal must not reveal existence; the retired `managedBy` migration grouped by identical manager set so two tenants sharing one manager were never merged.
- [[container-ownership-transfer]] — a project moves to another team with its applications and APIs following by reference, as one conditional write on every backend; owner of the team it leaves, member of the one it joins; previewed with counts; one audit entry both teams read; the migration that made personal teams single-member.
- [[project-is-the-only-container]] — since spec 099 the old Project entity (now a retired project) is gone and the project (stored as a bucket) is the only container: an application and an API store `bucketId`, a server-only key; why (a membership list that let a client fall out of its old project into a consent bypass on the Default project, `LIMIT 1` lookups, no product value), the flat-in-the-pool industry pattern, what replaced each per-old-project behaviour, and the upgrade that refuses before it writes.
- [[application-page]] — spec 107: situations are console-only presets that expand into the create route's fields (never a `template` input); every application has its own page (Connect, Settings) and the edit modal is gone; the server states `connection` (from the served discovery), `hasSecret`, a PATCH-minted secret once, `agentClients` and resource `connection` (server-side because the console CSP is `connect-src 'self'`); `ClientUsage` records first/last token per operator-created client, never awaited, ≤1 write/min/instance.
- [[prompt-create]] — `prompt=create` (Initiating User Registration, Final 2022) is carried by the login prompt as reason `create_prompt`, opens the interaction on `/registration`, is satisfied by the sign-in at its end so it cannot loop, falls back to the sign-in page where the project takes no sign-ups (the spec leaves that undefined), and makes discovery publish `prompt_values_supported` (classified `oidc`); `/admin/signup` is the console's door to it.
- [[admin-console-signin]] — the console is a relying party on its own issuer and must verify the ID token; the advertised alg list contains `HS256` and is a boot snapshot, `assertPayload` skips future-`iat` whenever `exp` is present, and no `azp` is ever emitted.
- [[admin-mcp-control-plane]] — an agent administers the instance by re-dispatching into the real admin routes, so there is no second implementation; a load-bearing tool catalogue, the audience boundary in both directions, two withheld deletions, and four traps (flat `id` collision, closed schema vs open-map body, Elysia eating the body, the model-graph lazy import).
- [[administrators-applications]] — spec 109: a super administrator registers sign-in-only applications in the Administrators project so internal tools admit administrators by team (`groups` = teams); refused every resource (it was handed the default project's root APIs before), writes withheld from agents; `groups` now always in the ID token; tool sign-out ends the administrators' sign-in; deactivation revokes.
- [[client-assertion-audience]] — which `aud` a client assertion may carry at the six client-authenticating endpoints: lenient by default because RFC 9126 §2 and CIBA §7.1 still require the token and endpoint URLs; the rfc7523bis issuer-only rule (CVE-2025-27370/27371) as an opt-in setting that FAPI implies and makes string-only; the default flips when the RFC is published, with what to re-read first; the endpoint value is a path, never a route name; a client assertion typed for another purpose is refused.
- [[enterprise-managed-authorization]] — spec 108: a project as the receiving authorization server for ID-JAGs (trust on the sign-in provider, a verifier of its own, one person ladder, grant-less tokens, re-submittable ID-JAG vs single-use plain assertion) and as the identity provider issuing them through RFC 8693 (outside-server connections with group rules, pairwise and email gotchas); deliberately stricter than MCP-EMA on client authentication.
- [[mcp-server-authorization]] — the server as an authorization server for *other* MCP servers: a declared resource is data read every time, five project-resolution rules whose third one answers D6 (and which every caller must pass the resource to), a `client_id` that is a URL and stores nothing, the administrative allowlist with its loopback interlock, and four things that cannot be done the obvious way — the branch order in `tryFindClient`, dot segments on a parsed URL, an expiry index on the `Client` area, and restricting a permitted redirect target.
- [[admin-plane-error-shape]] — the admin plane answers `{ error: 'admin_error', message }`; the root OAuth handler is registered first and silently replaced it with `server_error` in the composed app, which every standalone-mounted admin spec missed.
- [[client-identity-from-database]] — `adapter('Client')` is the single source of client identity; the adapter is read every call and the LRU memo caches only validated objects, keyed by property hash.
- [[client-registration-attributes]] — every rule the registration validator applies to an attribute lives on its one entry; declaration order is the stored key order, two precedence lists decide which refusal a two-rule violation gets, and the structural layer stays in `ClientSchema` on purpose.
- [[project-is-an-issuer]] — a project (stored as a bucket) is addressed in the URL and is its own issuer; the Default project keeps the bare one, the two reserved projects are not addressable, and a token records which project minted it. A project holds exactly one address: a path segment, a hostname (since 056) or a subdomain of the instance (since spec 101), resolved through one derived `addressOf` with an `unaddressed` state that exists because the issuer and the cookie fall back differently.
- [[subdomain-project-addresses]] — spec 101's third address form, `<slug>.<instance host>`: the slug plus a `subdomain` marker, derived and never stored so it follows `ISSUER`; `addressOf` tests it before path; `hasOwnOrigin` for cookie, interaction binding and resume; hostname asked before subdomain and each project at one address only; reserved labels and the RFC 5891 encoded-label rule; a unique sparse `slug` index with one accepted race, a duplicate-slug pre-check and a repair of MongoDB's stored `slug: null` in `db:setup`; `projects.addressForms` read only when a form is chosen; `can.addressForms` is an ordered list; audit `from`/`to` are issuers.
- [[plans]] — spec 102: a project is on a plan (Free built in) that limits what its team may create, enforced only while `plans.enabled` is on and never for a super administrator or a System project; the plan is recorded on the project at creation (and by a migration), so changing the default moves nobody; checked in the route before the audit write; refusal is 409 `plan_limit`; Free generates the slug and refuses enterprise sign-in (generic OIDC, single-organisation Microsoft); the active-user cap pauses only self-service sign-ups and fails open.
- [[cookie-path-scoping]] — `(name, domain, path)` identifies a cookie, so `remove()` — which takes its `Path` from the route's schema (`/` in practice), never from the cookie — clears a different cookie than the one the browser keeps sending.
- [[typebox-dual-type-resolution]] — `tsc` resolves TypeBox to CommonJS declarations for Elysia and ES module ones for this repository, so schemas and TypeBox errors crossing to Elysia fail to type-check; meet Elysia on shape, and never force one set through `tsconfig` `paths`, which Bun honours at runtime.
- [[remember-me-session-retention]] — the "Remember me" checkbox was decorative for the life of the product: four independent breaks on one path, each sufficient alone; `transient` is the negative and absent means remembered; omitting `expires` works because `set()` resets from the schema's attributes; two tests were named for the distinction while proving nothing about it.
- [[single-use-under-concurrency]] — a code, a rotating refresh token, a pushed request and a replayed `jti` are single use because `consume` answers whether *this* call spent the record and `create` stores only when the id is free; until 2026-09-29 each decided on a copy read earlier, so parallel requests all won.
- [[interaction-browser-binding]] — the uid is in every URL and is no secret; the `_interaction` cookie's value (`cookieID`) is what binds a sign-in to its browser, and from `53341c6` until 2026-09-28 it was read and never compared, which let a uid holder take over a second-factor enrolment.
- [[cross-site-sign-out-post]] — `POST /logout` is not the GET mounted twice: a relying party's sign-out form is cross-site, `Lax` withholds the session cookie, and handled bare it overwrites the sign-in with an empty session and says "signed out"; it is bounced once through a same-origin form instead.
- [[end-user-cookie-attributes]] — a cookie's attributes come from whichever route's schema is running, so the weakest schema naming a cookie decides what the browser stores; two schemas named `_session` and the `/ui` one carried no attributes at all.
- [[end-user-lifecycle]] — deactivation, the local lock and deletion end access at once (back-channel logout, then the account-owned sweep); provisioned users are read-only locally; username/externalId uniqueness rides on derived scalar keys; profile → claims table; an address change is refused before audit when taken, and a verification message proves only the address it reached; `passwordSet` says whether a chosen password opens the account.
- [[deletion-and-revocation]] — revoke, cascade and guard are three different operations; ownership is declared per storage area and read by one engine; two areas no grant walk reaches.
- [[project-groups]] — roles are gone: a project's end users are grouped by groups (stored as bucket groups; members as records, not a list, after checking that no directory caps a group; every refusal decided before the first write, one transaction except on a standalone `mongod`), relying parties read them from a built-in `groups` claim (display names, a userinfo reference above 200), SCIM serves `/Groups`, and the administrators' `super_admin` is membership of the reserved Super administrators team.
- [[global-token-revocation]] — a project's upstream provider (Okta Universal Logout) ends everything a user holds here with one signed request; built on an expired individual draft behind an off-by-default flag, as one format over a format-neutral core whose refusals no setting can relax (Keycloak CVE-2026-18569); a second, cooldown-keeping key cache for presented JWTs; audited under the new "sign out everywhere".
- [[upstream-back-channel-logout]] — a project receives OIDC Back-Channel Logout from Keycloak, Auth0 and Ping and ends the sessions that came from the named upstream session (or, for a `sub`-only token, that person's sessions from that provider), keeping offline access; a session now records its upstream origin (provider + digest of `sid`) and an `UpstreamSession` record maps an upstream session to its account; the core learned where each format carries our client id; 400 for every refusal and fault, the fault still recorded (fifth capture site).
- [[scim-provisioning]] — a project provisioned by an enterprise directory over SCIM 2.0 through a provisioning connection: a never-stored `scim-<id>` client with a hashed secret, a built-in per-project resource arm ahead of MCP's, opaque tokens, its own errors, parser and per-connection limiter, own filter/patch code instead of the libraries the issue named, a correlation step that ends the federation ladder, and the three deviation settings with why each defaults as it does.
- [[scim-credential-overlap]] — replacing a SCIM connection's client secret or static token keeps the old value working until the directory has used the new one and gone an hour without the old, 24 h at most, because Entra's and Okta's connection tests use the new value before Save; tokens carry `credentialRef`, so an administrator's retire/stop/revoke sweeps only the old value's tokens and an end by itself sweeps nothing; keys and kind changes replace at once; static tokens expire (90 days or a year, RFC 7644 §7.4) with a backfill migration.
- [[end-user-onboarding]] — registration and email verification are per project; the door resolves on GET as well as POST, a correct password for an unverified account is sent what it needs, the sign-in page links only to open doors, codes are hashed and capped, an administrator's create follows the project's verification policy, and SMTP is read live from its own store, not from `ApplicationConfig`.
- [[project-workspace]] — a project opens on an Overview (needs attention, issuer and discovery to copy, sign-in at a glance, counts from a summary using `tally()`) and keeps name, address, ownership and a Danger zone on Settings; `changeAddress`/`delete` became state-aware (an owner changes an unused path or, since spec 101, subdomain; only owners delete a project holding accounts); address change previews by name and commits with `expect`; host arrivals clear on an address change.
- [[project-soft-delete]] — since spec 090 deleting a project schedules its destruction 30 days out: every door at its address answers as absent, the default `findAccount` refuses its tokens anywhere else, nothing in it is destroyed, and Restore brings it back with sessions intact; one guard keyed on the mounted route pattern refuses every admin write and tells strangers nothing; `destroyBucket` (Delete now and the hourly pass) is claimed, recorded once as the admin or `system:retention`, and destroys the project record last so a failure is finished by the next pass; address caches expire after 60 s so every instance converges.
- [[project-users-workspace]] — the Users tab reads one server page at a time with search and filters in the address; each person has a page (Profile, Sign-in methods, Groups, Activity) with acts at their confirmation class; no save spans two requests; the group member picker searches the server; account components shared with phase 4.
- [[end-user-support]] — since spec 089: an invitation is a password-reset challenge with `purpose: 'invite'` and 7 days (and the reuse fixed a reset link that survived an email change, and a 24 h supersession pointer); mark verified is a named act; sessions are read from grants and per-app sign-out never extends the session; local users get the directory's profile shape, and the profile now wins over stored claims; four bulk routes write one audit entry per person; member search reuses the prefix search through `memberOf`.
- [[console-federation]] — administrators sign in through the administrators' project's providers: super administrators configure them; there every link needs the password proof and a closed sign-up closes creation (a created administrator gets a personal team, never the privilege); passwords go off only from a session that came in through a linked provider, one reachability predicate refuses every change that would shut the console, `admin:password-sign-in` is the server-side way back; agent writes there are high-consequence via `highWhen`.
- [[admin-console-frame]] — every console screen has an address (one route table for the server's 404 and the client router; sign-in returns via a twice-validated `next`); project responses state `can`, which the routes decide through, so the console hides what it may not do and disables with a reason what state blocks; one C0–C4 confirmation table; feedback only through antd `App` (static `message`/`Modal` are lint errors); the admin 422 no longer echoes the submission.
- [[project-sign-in-policy]] — a project PATCH decides rights, then refusals (no way in; verification without mail on every project; the administrators' project's guards), then a counted preview for any change that tightens sign-in, applied only with `confirm` and the same `expect`; the tally's `withoutEnabledLink` and `passwordWithoutAuthenticator`; new projects closed; signing an administrator out and resetting their authenticator.
- [[provider-connection-group-pages]] — spec 084: a page each for providers, provisioning connections and (end-user) groups; wizards whose last step (who a first sign-in creates; the deprovisioning safeguard) has no default; trust-widening saves asked by name; the hold panel listing refused removals; `SecretReveal`; the group hand-over as C4.
- [[admin-project-settings]] — the administrators' project is edited on the ordinary project settings through a narrow loader, never by opening the shared ones; a guard per setting (verification needs mail and your own address proven) instead of a blanket refusal; administrator sign-up with a personal team; federation into the console is a separate feature.
- [[monthly-active-users]] — every project counts the distinct people it issued tokens to, per UTC month and day: one recording site in `executeGrant` (a call, not a listener), the project `findAccount` resolved rather than the token's root-served `bucketId`, the kind on the artifact because a sign-in followed by consent sits in `lastSubmission`, marks counted at read instead of counters (exact, no transaction), insert-if-absent freezing with a five-minute grace, unowned areas so deletions keep the history, and the deferred list of who.
- [[error-store-capture-sites]] — recorded faults are captured in seven places: two because the global handler stands aside on the `adminPlane` *marker* and only a deliberate `AdminError` carries one, the third because a fault delivered to a client by redirect returns before the handler records it (filed at 500, no reference in the URL), the fourth SCIM's own handler, the fifth the upstream back-channel logout receiver, which must answer a fault 400, the sixth the device-flow completion, the seventh the activity recorder, whose request succeeded; `set.status` may be a status name, so an un-narrowed `>= 500` test silently records nothing.
- [[interaction-error-delivery]] — every error that ends an authorization request, at `/auth` or after the interaction pages, is delivered to the client by one module; on resume the boundary is the restored request, not a list of errors, which keeps untrusted-interaction failures on-page by construction; the client and redirect URI are re-checked at delivery, for a code as much as an error; consent refusal is an interaction result, not a throw.
- [[untrusted-redirect-confirmation]] — an authorization error for a client whose redirect URIs no operator vouched for (self-registered, or from a metadata document) is offered on a confirmation page instead of redirected, per RFC 9700 §4.11.2 as its editors read it; trust is provenance, not id shape; one answer description feeds both the redirect and the page; the page denies framing despite its off-origin form.
- [[error-store-is-not-flag-gated]] — the admin operation set is invariant under capability switches, guarded twice; gating an admin route also splits the console from the agent surface, which re-dispatches without the gate plugin — so the flag is reported in the payload and the agent purge is withheld outright rather than opt-in.
- [[feature-flag-gating]] — flat dotted keys on `ApplicationConfig`, an overrides document holding only edited keys, a derived `configuration` re-derived in place whenever a save is applied, and the `onRequest` gate that makes a disabled endpoint answer as unserved.
- [[first-run-setup-had-two-surfaces]] — `GET /admin` is the only bootstrap surface; the deleted `/admin/setup` twin pointed at an unserved bundle and rendered a blank page nothing linked to.
- [[html-response-security-policy]] — one constructor builds every HTML response and hashes its own inline scripts; a global lifecycle plugin was measured and misses the error page and the named admin instance.
- [[non-html-response-hardening]] — the companion policy for everything that is not a page, written from one `onRequest` hook; there is deliberately no page-detection branch because a page's own `Response` header wins over the merge, the CORS mount-order caveat does not bind a pre-routing hook, and the single-writer guard is a substring scan a comment can fail.
- [[end-user-colour-scheme]] — every end-user page follows the device's light or dark scheme with no script, no cookie and no setting: a `--fox-*` palette plus a dark block of antd's `--ant-*` values that out-ranks antd's own; the hydrated pages now inline their custom properties for the first paint; antd's defaults failed WCAG AA in both schemes and are corrected per scheme; logos and the TOTP QR stay on light plates.
- [[end-user-languages]] — every end-user page and email in English, Russian or Simplified Chinese: decided once per sign-in (choice cookie → `ui_locales` → stored locale → browser → English, RFC 4647 Lookup with a script check for Chinese), a no-script switch only between English and the visitor's own language, typed whole-sentence catalogues whose values are never templates, protocol fields untouched.
- [[interaction-page-families]] — every end-user screen is either the hydrated antd shell or a plain self-contained page; a hydrated page without props erases its own server-rendered message, silently and only in a browser; antd's `zeroRuntime` never reaches zero because a second, ungated hook always injects a small cssVar block.
- [[model-graph-import-order]] — `lib/models/` has a cycle, so a cold entry throws a TDZ `ReferenceError`; enter through `test_helper` first, and the existing drift guard only passes by accident.
- [[mongodb-test-fidelity]] — the production backend carried zero coverage by constitutional rule, until the rule shipped a server that could not boot; two tiers now, split on whether a property can be proven without a server, and three import-time barriers in the way.
- [[test-admission-rule]] — a test proves a user case or a security invariant, or it is deleted; the guards were never structure tests because they enumerate the mounted route table, the templates are two because a completeness guard has no trigger, and a change-detector can sit inside a real guard — which is why classification runs per case, not per file.
- [[spec-file-isolation]] — nothing reaches from one spec file into the next: the preload restores spies, the clock, the environment and the settings at the boundary, marked by a resolver that watches the next spec file resolve, and `bootstrap()` replaces every store and forgets every cache built from one; reset rather than detected, because Bun cannot list its spies and at the boundary nothing may want the leftovers; case order inside a file is still `--randomize`'s to show; the test process binds no port, which on Windows had shared a local server's connections.
- [[postgresql-backend]] — a second datastore behind the same contract; two expiry designs reversed by reading the call sites, a tolerant decoder that hid a jsonb encoding defect for a commit, why the fidelity checks are scripts, the migration layer's four states and its `rerunnable` sentence, the liveness/readiness split the lazy handle forced, and the `text_pattern_ops` prefix indexes the users search needs (MongoDB builds none).
- [[per-origin-rate-limiting]] — mounting before the feature gate is a correctness call, not an optimisation; the refusal renders at the root because the throw precedes routing; counters are bounded, in-process and never persisted, which makes it a resource protection rather than a security boundary.
- [[override-seams-vs-dead-code]] — an empty addon body is an extension point's default, not an abandoned stub; source modules import the accessor rather than the implementation, so an importer census reports live seams as dead, and resolving a removal candidate by symbol name instead of path nearly deleted a live `urlFor`.
- [[pairwise-identifier-salt]] — the pseudonym is a relying party's account key, so its salt is stored server state, never the hostname; an unusable salt fails closed at the token endpoint and is never replaced, and the logout notification derives its `sub` a layer away in the claim pipeline.
- [[form-action-redirect-chain]] — a browser checks form-action against every hop of a submission's redirect chain, so `'self'` blocked the hand-off to a foreign callback after the code had already been issued; only a real browser can see it.
- [[connected-apps-page]] — since spec 095 each project has `/account/apps`: the person is read from the project's own session (no token), a signed-out visitor signs in through a synthesized, never-stored `account.<bucketId>` client with `response_type=none` and no grant type, a GET never removes anything, removal needs a ≤ 15-minute sign-in, a same-origin post and a per-session anti-forgery value and is the administrator's `endApplicationAccess`, recorded as `enduser:<bucket>:<account>` / `self-service`; grants now record their project.
- [[consent-screen-decisions]] — since spec 092 the consent page says who asks, what for and how long: three provenance tiers with self-registered tested first, no positive trust signals, at most one warning (admin > loopback-only > device > amber unverified), undescribed resource scopes default to "act", the admin MCP recognised by resource, "keeps access until" only when a refresh token will really be issued, the POST bound to the shown account, a sanitised `<bdi>` name with a vendored UTS #39 skeleton, a server-only header, and one English text catalog; since spec 093, unticked checkboxes for a client an operator marked `consent.partial` (sign-in items fixed, refusals offered again only on `prompt=consent`); since spec 094, an operator-uploaded logo (PNG/JPEG/WebP ≤ 64 KiB, its own `ClientLogo` area, never `logo_uri`) and https policy/terms links on a redirect host, both only for this organization's own app and the logo never on a device or loopback page.
- [[client-primary-colour]] — since spec 106 an administrator gives an app a `#rrggbb` primary colour (a base key on the client record, so registration cannot carry it); it paints the sign-in, registration, two-step and consent pages only when one per-sign-in decision allows (this-organization, not a device flow, not loopback-only — the logo now follows it too, closing a 094 gap); lightness moves to the nearest AA shade per scheme, searching over antd's dark seed because the dark algorithm re-derives `colorPrimary` and `colorLink`; the colour must ride `window.PROPS` or hydration resets it, and the dark-block memo keys on it. Since 2026-10-21 the same decision names the app (and the project, always) at the top of the sign-in, registration and two-step pages.
- [[first-consent-grant-id]] — an interaction's grantId is a hint, not proof of storage; a first consent resolved it with find() and answered 401 invalid_token for a missing record, and the harness's pre-seeded grant hid the branch.
- [[login-door-throttle]] — the second factor's failure window moved to the password door; two horizons whose confusion silently removes the escalation, a ceiling that reads the project's second factor rather than its id, the reset flow as the escape hatch, and a casing bypass that passes every lower-case test.
- [[loopback-redirect-port-matching]] — a native client's loopback redirect may differ from its registration in the port alone; registration-time validation knew this shape and request-time matching did not.
- [[pkce-verifier-length]] — the challenge is 43 characters because it is a digest; the verifier is 43..128 because the client chose, and pinning it at 43 refused conformant clients at schema validation with a 422, three steps upstream of the 401 they saw.
- [[self-service-password-reset]] — a reset secret is hashed at rest, expiry-checked in code because Mongo's TTL monitor is lazy, never consumed by a GET, and refused for the reserved administrators' project; one accepted page for every outcome.
- [[upstream-federation]] — a project may accept sign-in through external OIDC providers; the flow is three hops because the interaction cookie provably cannot survive the trip to an upstream, both round-trip records are keyed by a digest of the value they never store, and linking to an existing account needs operator trust *and* a verified assertion.
- [[federation-try-signin]] — an administrator tries a provider through the project's real callback and sees the provider's answer and what a real sign-in would do, with nothing written: the ladder split into reads-only `decideFederatedAccount` and `applyDecision`, a try decided only by the stored record, bound to a digest of the console session cookie (RFC 9700 §2.1.1), read by polling because the Strict console cookie cannot survive the return from the provider; works on a disabled provider; excluded from MCP as inapplicable.
- [[recognised-provider-divergences]] — why Microsoft, Apple and GitHub each needed more than a catalogue row: a templated issuer no equality check can satisfy, a credential that expires in six months so it is minted per exchange, and a provider that asserts no identity at all — plus the finding that three of four providers were silently getting no PKCE because support was inferred from metadata that under-reports it.
- [[rich-authorization-requests]] — `authorization_details` end to end on the code and refresh flows; the declared parameter schema is a runtime coercion contract, and details reach a token only when a resource server resolves.
- [[refresh-token-chain-bound]] — a browser application's rotated refresh tokens inherit the chain's remaining lifetime, decided from `iiat`/`rotations` on the token itself; dead from `54ba556` until 060, masked by the equal default grant lifetime.
- [[stored-document-schemas]] — every store document type is a TypeBox schema, and every PostgreSQL/MongoDB read is checked against it: dates and Mongo's `undefined`-as-null translated back by the schema, a mismatch thrown as a defect rather than read as missing.
- [[token-payload-access-contract]] — model state lives under `.payload.*`; reading a bare field yields `undefined` silently, and payload schemas are composed per token type.
- [[two-meanings-of-origin]] — `origin` names the caller's network address on the record and the code location on the occurrence, so the outbound event carries both under different names and must never merge them; the location is sendable only because no stack is kept, the permitted list is enforced one level deep, and grouping cannot be disturbed because a client fingerprint suppresses the destination's algorithm entirely.
- [[authentication-context-reporting]] — the server owns which sign-ins it can tell apart and an operator owns their names, because context matching is exact string comparison; the advertised set is derived so it cannot overclaim; it was two gaps not one (a getter read past the payload, making an essential `acr` permanently unsatisfiable); the refusal is delivered from the resume route by the general rule ([[interaction-error-delivery]]); and the backchannel breaks the same invariant the other way — a token that should not exist rather than a loop.
- [[amr-reporting]] — every ID token from a sign-in states its methods (`pwd`; `pwd`+`otp`+`mfa`; none when federated), keyed on the same distinctions as `acr`; declaring the claim was never enough because it must also be requested, so it is written past the mask like `sid` and advertised whatever the stored claims setting says; never fails a request; forwarding a trusted provider's `amr` is deferred with its cost written down.
- [[ipsie-sl1-profile]] — the `ipsieSl1.enabled` switch: the IPSIE SL1 and Common Requirements rules that cannot be defaults (no `http` redirects, preregistered clients only, `code` only, DPoP at every grant, PS256/ES256/EdDSA with PS256 written for clients that registered none, binding `acr_values`, string audience); refused until DPoP, PKCE, encryption, registration's token and a PS256 signer at every issuer are in place; a readiness answer before switching; who is exempt and why; what SL1 still needs (step-up, federated `amr`, other issuers' JWTs).
- [[session-expiry-claim]] — every ID token says when the application must send the person back (IPSIE SL1): `iat` plus an operator bound (24 h, NIST AAL2), never past the browser session's end and never under five minutes; computed where `iat` is decided; advertised like `amr`, reserved and dropped from stored claims because reserving alone left a stored value reaching UserInfo; an upstream provider's own `session_expiry` caps the session's `exp`, so every reader sees it; the SL1 gaps left are listed.
- [[totp-second-factor]] — one project boolean turns a password door into a two-key one; the algorithm is in-repo because the RFCs publish test vectors, and four placements of state buy deletion integrity, expiry, un-guessable enrolment and a throttle that survives a new interaction for free.
- [[settings-console-descriptor]] — the console's panes, summaries, units, risk marks and now the restart class are fields on the catalog descriptor, so the page holds no second list of settings; the demotion criterion is "is there a question an operator could answer to set it", a key's absence from the catalog removes it from both the console and the agent surface, and a saved setting is in force without a restart unless its descriptor says otherwise.
- [[signing-keys]] — every issuer's keys, the root's included (owner `'#root'`), are `bucketKeys` records with one lifecycle: generate (published) → promote after the window (one signer per algorithm) → retire with a typed-kid confirmation → hidden after a day, never deleted; no restart; the leaf `keystore.ts` is a mirror of the root's signing and encryption keys.
- [[user-code-mask-entropy]] — the asterisks in `deviceFlow.mask` are the whole of a user code's entropy, so a mask with none issued the same code to every device and passed a character check that never asked for shape; the floor is zero-vs-nonzero because how many is enough is an operator's judgement, and the check is scoped to the flow being enabled without leaving a hole.
- [[security-assurance-evidence]] — SECURITY.md was policy without proof; now a threat model (RFC 9700 shape, every control row names its source and its spec, and the Known limitations are the evidence), an assurance page that says what has not been done, and a Security workflow (CodeQL incl. `actions`, `bun audit` on both lockfiles, dependency review, Trivy to code scanning) plus Scorecard and Dependabot; the image scan deliberately does not fail the build, actions stay on major tags for now.
- [[unknown-request-parameters]] — six endpoints must ignore a parameter they do not define (RFC 6749 §3.1 *and* §3.2, RFC 8628, CIBA, RFC 9126 by reference, RFC 9101 for the Request Object); once absence means "ignore", every deliberate refusal has to be declared as `t.Undefined` or it silently becomes acceptance; `normalize: true` is the wrong instrument because it also cleans headers and breaks mTLS-bound tokens, and it cannot reach the Request Object at all.
