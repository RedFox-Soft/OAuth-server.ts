代理后的应用决定谁可以打开每个路径。由代理检查令牌的 API 决定令牌可以调用哪些工具。这两部分分别见[在 Web 应用前加上登录](/zh-cn/docs/get-started/put-sign-in-in-front-of-a-web-app/)和[在代理处保护 MCP 服务器](/zh-cn/docs/get-started/protect-an-mcp-server-at-your-proxy/)。本页在此基础上添加条件。

条件的意思是“并且只有当”。它不会让以前不能进入的人进入。它只能收紧访问。

## 有哪些条件 {#kinds}

| 条件                     | 检查什么                                   | 适用于    |
| ------------------------ | ------------------------------------------ | --------- |
| **From where**           | 地址在您的某个范围内，或不在任何范围内     | 应用、API |
| **When**                 | 时刻在您设定的时间内，按您选择的时区       | 应用、API |
| **Attribute**            | 此人的部门、职位或其他字段是您设定的值之一 | 应用、API |
| **Groups**               | 此人属于您的某个用户组                     | API       |
| **Ask to sign in again** | 此人在 N 分钟之内登录过                    | 应用      |

应用的用户组已经写在每个路径的规则里，因此只有 API 才把用户组作为条件。

同一个条件内的值用“或”组合：“来自办公室或来自 VPN”。不同的条件用“且”组合：“来自办公室，且在工作时间”。每条规则每种条件最多一个。

## 条件如何作用于路径 {#paths}

谁可以打开某个路径，仍然由最长的匹配路径决定。条件沿路径向下累加：`/` 的条件作用于所有路径，`/admin` 上的条件作用于 `/admin` 及其下的所有路径，并叠加在 `/` 的条件之上。路径可以添加条件，但不能去掉上级路径的条件。公开路径没有条件。

项目按固定顺序判断：

1. **From where** 和 **When**，在任何人登录之前。地点或时间不对的人会被直接拒绝，不会被要求输入密码。
2. 此人是否已登录、是否可以登录、是否在规则的用户组中。
3. **Attribute**。
4. **Ask to sign in again**，最后判断。不会让人先登录、之后又被拒绝。

## From where：让代理传递地址 {#from-where}

此人的地址只有您的代理知道。浏览器可以在标头里写任何地址，因此只有当代理证明地址是它自己写的，项目才相信这个地址。

1. 在应用或 API 的 **Connect** 页面，打开 **Your proxy passes people's addresses** 这一步，点击 **Issue a proxy key**。复制密钥：它只显示一次。一个项目最多有两个密钥，因此可以替换其中一个，而代理不会有被拒绝的时刻。
2. 把该页面配置中的行加入您的代理。它们用连接来源的地址覆盖 `X-Forwarded-For`，并加上密钥。对于 Caddy，在 Caddy 运行的环境中设置 `FOXAUTH_PROXY_KEY`。对于 nginx，把密钥填到配置中写着 `<FOXAUTH_PROXY_KEY>` 的地方。
3. 运行该页面给出的测试。它会通过您的代理发送一个伪造的地址。这一步不能变成红色。

在收到带密钥和公网地址的检查之前，无法保存网络条件。因此一次保存不会把所有人挡在外面。

### 项目相信什么 {#believed}

- 只相信一个以普通方式写出的地址。两个地址、端口、方括号或少见的写法都会让地址变为未知。
- 未知地址不能通过任何网络条件，无论是“只允许来自”还是“不允许来自”。
- 私有地址，例如负载均衡器或容器网络的地址，对于“不允许来自”视为未知。当代理报告这样的地址时，Connect 页面会提示。
- 不支持代理前面的 CDN，Cloudflare 除外：前提是您的代理只接受来自 Cloudflare 地址的连接。
- 地址只会与您的范围比较。它不会写入日志，也不会被保存。

VPN 或住宅代理仍然可以绕过地址范围列表。网络条件能拖慢攻击者，但无法阻止。

对于 API，地址属于调用它的机器。托管的助手从它们自己的云端调用，而不是从此人的网络调用。

## When：开放时间 {#when}

选择日期和时间（以 15 分钟为单位），以及读取这些时间所用的时区。时区为应用或 API 设置一次。结束早于开始的时间段跨越午夜：“周五 22:00 至 06:00”表示周五晚上到周六早上。

在开放时间之外到来的人，会看到应用何时重新开放，按应用的时区显示。

## Attribute {#attribute}

选择一个属性及其取值。这些属性由管理员或目录为此人设置：部门、分部、组织、成本中心、员工编号、职位，或管理员设置的 claim。由此人的外部登录提供方提供的 claim（例如姓名或头像）不能选择：此人自己可以修改它们。

控制台会显示项目中有多少人符合。没有任何人符合的条件无法保存。

## Ask to sign in again {#fresh}

选择 15 分钟、1 小时、8 小时、1 天，或从 5 分钟起的自定义值。当此人的登录更早时，浏览器会被转去重新登录，登录页面会说明原因。不是页面的请求会得到 `401`。

- 在后台加载数据的页面（例如仪表板）会停止工作，直到此人重新加载页面。请把它用于管理路径，而不是整个应用。
- 如果项目在登录时要求身份验证器应用，重新登录也会要求输入验证码。
- 通过外部提供方登录的人会被要求在那里重新登录。那次登录有多新，由该提供方决定。

## API 的用户组和属性 {#api}

在 API 那一行选择 **Access…**。它的第一部分 **Who can call it** 包含 API 的条件。这些条件在工具表之前生效。

关于此人的条件需要一个代表某个人的令牌。以下令牌不代表任何人，会被拒绝：

- 应用为自己获取的令牌，没有对应的人；
- 某个应用的令牌，而这个应用在每个应用中给人不同的标识符（pairwise）；
- 本版本之前签发的自包含令牌，其中没有说明此人何时登录。

保存时，控制台会列出令牌将被拒绝的应用名称。被锁定或停用的人会立即被拒绝。被移出用户组的人会在一分钟内被拒绝。

## 保存前先检查 {#check}

应用 Access 选项卡上的 **Check access** 接受应用中的地址、某个人、网络地址、某个时刻，以及此人登录了多久。它按项目判断的顺序列出每个条件，并标上 ✓、✗ 或 ?。您留空的输入会显示“?”。

让更多人进入的更改会先请求确认，并逐个路径列出放宽了什么。只收紧访问的更改会立即保存。FoxAuth 控制台本身永远不受这些条件限制，因此规则不会把您挡在控制台之外。

## 升级与回滚 {#rollback}

第一个带条件的版本会标记数据库，使更早的版本拒绝在其上启动。更早的版本无法执行条件，因此不能运行。您无法回滚到此版本之前。在滚动部署期间，仍在运行的旧进程会对带条件的应用或 API 返回错误，直到被替换。它永远不会放行请求。
