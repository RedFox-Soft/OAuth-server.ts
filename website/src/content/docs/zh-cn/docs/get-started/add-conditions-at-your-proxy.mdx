代理后的应用决定谁可以打开每个路径。由代理检查令牌的 API 决定令牌可以调用哪些工具。这两部分分别见[在 Web 应用前加上登录](/zh-cn/docs/get-started/put-sign-in-in-front-of-a-web-app/)和[在代理处保护 MCP 服务器](/zh-cn/docs/get-started/protect-an-mcp-server-at-your-proxy/)。本页在此基础上添加条件。

条件的意思是“并且只有当”。它不会让以前不能进入的人进入。它只能收紧访问。

## 有哪些条件 {#kinds}

| 条件                     | 检查什么                                           | 适用于    |
| ------------------------ | -------------------------------------------------- | --------- |
| **From where**           | 地址在您的某个范围内，或不在任何范围内             | 应用、API |
| **Network facts**        | 地址不属于 Tor、VPN 或托管服务，或位于您选择的国家 | 应用、API |
| **When**                 | 时刻在您设定的时间内，按您选择的时区               | 应用、API |
| **Attribute**            | 此人的部门、职位或其他字段是您设定的值之一         | 应用、API |
| **Groups**               | 此人属于您的某个用户组                             | API       |
| **Ask to sign in again** | 此人在 N 分钟之内登录过                            | 应用      |

应用的用户组已经写在每个路径的规则里，因此只有 API 才把用户组作为条件。网络信息是 **From where** 的一部分，不是单独的条件。API 没有 **Ask to sign in again** 条件，但可以在它自己的 Access 选项卡中要求两步登录或近期登录：请参阅[连接时要求两步登录或近期登录](/zh-cn/docs/get-started/protect-an-mcp-server-at-your-proxy/#require-a-code-or-a-recent-sign-in)。

同一个条件内的值用“或”组合：“来自办公室或来自 VPN”。不同的条件用“且”组合：“来自办公室，且在工作时间”。每条规则每种条件最多一个。

## 条件如何作用于路径 {#paths}

谁可以打开某个路径，仍然由最长的匹配路径决定。条件沿路径向下累加：`/` 的条件作用于所有路径，`/admin` 上的条件作用于 `/admin` 及其下的所有路径，并叠加在 `/` 的条件之上。路径可以添加条件，但不能去掉上级路径的条件。公开路径没有条件。

项目按固定顺序判断：

1. **From where** 和 **When**，在任何人登录之前。地点或时间不对的人会被直接拒绝，不会被要求输入密码。
2. 此人是否已登录、是否可以登录、是否在规则的用户组中。
3. **Attribute**。
4. **Ask to sign in again**，最后判断。不会让人先登录、之后又被拒绝。

不拒绝、而是要求重新登录的网络信息，与 **Ask to sign in again** 一起在最后判断。

## From where：让代理传递地址 {#from-where}

此人的地址只有您的代理知道。浏览器可以在标头里写任何地址，因此只有当代理证明地址是它自己写的，项目才相信这个地址。

1. 在应用或 API 的 **Connect** 页面，打开 **Your proxy passes people's addresses** 这一步，点击 **Issue a proxy key**。复制密钥：它只显示一次。一个项目最多有两个密钥，因此可以替换其中一个，而代理不会有被拒绝的时刻。
2. 把该页面配置中的行加入您的代理。它们用连接来源的地址覆盖 `X-Forwarded-For`，并加上密钥。对于 Caddy，在 Caddy 运行的环境中设置 `FOXAUTH_PROXY_KEY`。对于 nginx，把密钥填到配置中写着 `<FOXAUTH_PROXY_KEY>` 的地方。
3. 运行该页面给出的测试。它会通过您的代理发送一个伪造的地址。这一步不能变成红色。

在收到带密钥和公网地址的检查之前，无法保存网络条件。因此一次保存不会把所有人挡在外面。

### 项目相信什么 {#believed}

- 只相信一个以普通方式写出的地址。两个地址、端口、方括号或少见的写法都会让地址变为未知。
- 未知地址不能通过任何网络条件，无论是“只允许来自”还是“不允许来自”。
- 私有地址，例如负载均衡器或容器网络的地址，对于“不允许来自”视为未知。当代理报告这样的地址时，Connect 页面会提示。
- 不支持代理前面的 CDN，Cloudflare 除外：前提是您的代理只接受来自 Cloudflare 地址的连接。
- 地址会与您的范围比较；使用网络信息时，还会在您服务器自己的 FoxTrust 快照副本中查找。这次检查永远不会把它写入日志行，也不会把它发送到任何地方。当某个路径拒绝某人或要求其重新登录时，因为您的代理用项目的密钥证明了这个地址，此人的 Activity 标签页会保留该地址 90 天。只要 **Look up network owner and location at FoxTrust** 开启（默认开启），服务器随后会把这个保留的地址发送到 FoxTrust 的 API，以便在旁边显示它的网络所有者、地区和城市（[FoxAuth 记录了用户的哪些信息](/zh-cn/people-records/)）。

VPN 或住宅代理仍然可以绕过地址范围列表。网络条件能拖慢攻击者，但无法阻止。网络信息可以挡住 FoxTrust 列出的 VPN 服务，但住宅代理仍然能通过。

对于 API，地址属于调用它的机器。托管的助手从它们自己的云端调用，而不是从此人的网络调用。

## 网络信息：Tor、VPN、托管服务和国家 {#network-facts}

地址范围列表写的是您知道的地址。网络信息说明一个地址是什么，即使您从未见过它：Tor 网络的出口、商业 VPN、数据中心，或者某个国家。它是 **From where** 中可选的第二部分，可用于应用的路径和 API。和地址范围列表一样，它需要上面步骤中的代理密钥和地址。

### 开启下载 {#network-facts-download}

网络信息来自 FoxTrust，一个 IP 信誉服务。FoxTrust 发布一个签名的快照，其中是它所知道的关于互联网地址的信息。您的服务器自己下载快照，自己检查它。

1. 超级管理员打开 **Settings → Integrations**，开启 **Network facts from FoxTrust**。默认关闭。所有套餐均可免费使用。
2. 之后，每个服务器进程每天下载一个约 13 MB 的完整文件，每小时下载一次更新。它每 5 分钟检查一次是否有新文件。只有在检查了文件大小、校验和以及 FoxTrust 的签名之后，才会使用该文件。
3. 设置下方的卡片会显示快照的生成时间、已有多久、包含多少个地址范围，以及最近一次失败（如果有的话）。

对于条件，用户的地址永远不会被发送给 FoxTrust 或其他任何地方。您的服务器只在自己的副本中查找它们，FoxTrust 只知道文件被下载了。显示一个人的活动所保留地址的网络所有者和位置，是另一项设置：**Look up network owner and location at FoxTrust**，它会把这些地址发送到 FoxTrust 的 API。

### 可以挡住什么 {#network-facts-categories}

在 **Network facts from FoxTrust** 下，勾选路径要挡住的内容：

| 选项                   | 包括什么                                                           |
| ---------------------- | ------------------------------------------------------------------ |
| **Tor**                | Tor 网络的出口。                                                   |
| **Commercial VPN**     | 只包括 FoxTrust 列出的 VPN 服务。公司自己的 VPN 不包括在内。       |
| **Hosting or a cloud** | 数据中心和云。内容分发网络以及一些公司访问互联网的出口也经过它们。 |

iCloud Private Relay 不在选项中，它的地址可以通过。FoxTrust 不把这些地址算作 VPN 或托管服务。

### 国家 {#network-facts-countries}

选择 **Only from** 或 **Not from**，然后选择国家。一个条件只能有两种列表之一，最多 250 个国家。

- 国家未知的地址无法通过 **Only from**，但可以通过 **Not from**。
- 代理自己私有网络中的地址没有国家，因此 **Only from** 会拒绝它。无论是类别还是国家，**Not from** 都会让它通过。
- 不使用地区和城市。

国家数据来自 DB-IP。控制台在显示国家的每个地方，都会同时显示数据许可证要求的那一行：[IP Geolocation by DB-IP](https://db-ip.com)，CC BY 4.0。

### 符合条件的地址会怎样 {#network-facts-outcome}

选择地址符合条件时会发生什么：

- **Refused**。在任何登录之前，此人会看到一个标题为“You can't open app.example.com from where you are”的页面，以他的语言显示。页面不会提到来源、类别或国家。您的代理会收到 `403` 和 `X-Auth-Reason: not_from_network`。
- **Asked to sign in again within N minutes**，只适用于应用。登录早于 N 分钟的人会被转去重新登录。N 从 5 分钟到一天。勾选 **with two-step sign-in**，还会要求验证码或通行密钥。此时控制台会显示与[在 Ask to sign in again 中要求两步登录](#with-code)相同的人数。

不符合条件的地址不会被要求任何操作。FoxTrust 对某个网络的判断可能有误，而要求重新登录比直接拒绝更温和。对于在代理处检查的 API，网络信息只能拒绝，因为检查令牌时没有可以送去登录的浏览器。不过 API 仍然可以通过它自己的设置要求两步登录或近期登录：请参阅[连接时要求两步登录或近期登录](/zh-cn/docs/get-started/protect-an-mcp-server-at-your-proxy/#require-a-code-or-a-recent-sign-in)。

规则那一行会用文字描述条件，例如“not from Tor, a VPN or hosting”或“only from Germany or Austria”。

### 网络信息未知时 {#network-facts-unknown}

在下载关闭时、第一个快照加载之前，以及已加载的快照生成超过 26 小时时，服务器无法说明一个地址是什么。这时，每个带网络信息的路径都会关闭，无论选择了哪种结果。

- 此人会看到一个标题为“app.example.com can't be opened right now”的页面，以他的语言显示。您的代理会收到 `403` 和 `X-Auth-Reason: network_facts_unknown`。
- 控制台会标出每个这样的路径，并说明原因。
- 加载新的快照后，这些路径会自动重新开放。

一次下载失败不会立即改变任何事。服务器会继续使用最后一个有效的快照，直到它超过 26 小时。

只有在下载开启时才能添加或更改网络信息。之前保存的条件在下载关闭后仍然保留，并会关闭其路径。

### 检查一个地址 {#network-facts-check}

在 **Check access** 中输入此人消息里的地址。控制台会在您服务器自己的快照副本中查找它，显示它的类别和国家，或者说明 FoxTrust 对它一无所知，并显示快照已有多久。地址不会被发送到任何地方。没有输入地址时，网络信息显示“?”。

智能体通过 `behind_proxy_app_update` 或 `resource_update` 设置网络信息，即 `network` 条件上的 `facts`。它可以用 `network_facts_lookup` 解释一次拒绝。

## When：开放时间 {#when}

选择日期和时间（以 15 分钟为单位），以及读取这些时间所用的时区。时区为应用或 API 设置一次。结束早于开始的时间段跨越午夜：“周五 22:00 至 06:00”表示周五晚上到周六早上。

在开放时间之外到来的人，会看到应用何时重新开放，按应用的时区显示。

## Attribute {#attribute}

选择一个属性及其取值。这些属性由管理员或目录为此人设置：部门、分部、组织、成本中心、员工编号、职位，或管理员设置的 claim。由此人的外部登录提供方提供的 claim（例如姓名或头像）不能选择：此人自己可以修改它们。

控制台会显示项目中有多少人符合。没有任何人符合的条件无法保存。

## Ask to sign in again {#fresh}

选择 15 分钟、1 小时、8 小时、1 天，或从 5 分钟起的自定义值。当此人的登录更早时，浏览器会被转去重新登录，登录页面会说明原因。不是页面的请求会得到 `401`。

- 在后台加载数据的页面（例如仪表板）会停止工作，直到此人重新加载页面。请把它用于管理路径，而不是整个应用。
- 设置了身份验证器应用的人重新登录时也会输入验证码。
- 通过外部提供方登录的人会被要求在那里重新登录。那次登录有多新，由该提供方决定。

### 使用两步登录或通行密钥 {#with-code}

在 **Ask to sign in again** 条件下（或在 **From where** 网络事实的“Ask to sign in again”结果下），选择 **any sign-in**、**two-step sign-in** 或 **a passkey**（仅当项目接受通行密钥时可选）。选择 **two-step sign-in** 后，只有包含身份验证器应用验证码、或在项目接受通行密钥时使用通行密钥，且不早于您所选时间（最长一天）的登录才能打开该路径，规则显示为“signed in with two steps within 15 min”。选择 **a passkey** 后，只有使用已确认通行密钥且在所选时间内的登录才能打开该路径，规则显示为“signed in with a passkey within 15 min”。

- 保存前，控制台会显示可以打开该路径的人中有多少人没有身份验证器应用、有多少人没有已确认的通行密钥（针对通行密钥条件），以及有多少人只能通过提供方登录。您需要按这些数字确认。只有可以管理项目用户的人才能开启它。
- 对于 **two-step sign-in**：有验证码的人会用密码和验证码重新登录，有通行密钥的人也可以改用通行密钥重新登录。对于 **a passkey**：只有已确认的通行密钥可以通过；密码和验证码、未确认的通行密钥以及提供方登录都不会通过。
- 没有验证码或通行密钥的人会看到一个显示您应用地址的页面。如果项目允许自行设置，他们可以在那里设置（或当场创建通行密钥），并在同一次登录中进入所打开的页面。否则，页面会请他们联系您。
- 通过提供方登录的人会被告知，这种登录方式无法打开该页面。
- 不登录就返回，会停在一个说明该页面需要两步登录或通行密钥的页面上。它绝不会重新开始同一次登录。
- 控制台的 **Check access** 让您选择此人的登录方式（仅密码、两步登录或通行密钥）。

## API 的用户组和属性 {#api}

打开该 API 的页面及其 **Access** 选项卡。它的第一部分 **Who can call it** 包含 API 的条件。这些条件在工具表之前生效。

关于此人的条件需要一个代表某个人的令牌。以下令牌不代表任何人，会被拒绝：

- 应用为自己获取的令牌，没有对应的人；
- 某个应用的令牌，而这个应用在每个应用中给人不同的标识符（pairwise）；
- 本版本之前签发的自包含令牌，其中没有说明此人何时登录。

保存时，控制台会列出令牌将被拒绝的应用名称。被锁定或停用的人会立即被拒绝。被移出用户组的人会在一分钟内被拒绝。

MCP 服务器的某一个工具可以带有自己的条件：用户组、**From where** 和 **When**。这些条件加在 API 的条件之上，永远不会取代它们。不满足这些条件的调用会被拒绝，而不会被要求重新登录。请参阅[单个工具的条件](/zh-cn/docs/get-started/protect-an-mcp-server-at-your-proxy/#tool-conditions)，那里也说明了这种条件挡不住什么。

## 保存前先检查 {#check}

应用 Access 选项卡上的 **Check access** 接受应用中的地址、某个人、网络地址、某个时刻，以及此人登录了多久。它按项目判断的顺序列出每个条件，并标上 ✓、✗ 或 ?。您留空的输入会显示“?”。API 的 **Access** 选项卡上也有自己的 **Check access** 卡片：请参阅[检查访问](/zh-cn/docs/get-started/protect-an-mcp-server-at-your-proxy/#tool-conditions-check-access)。

让更多人进入的更改会先请求确认，并逐个路径列出放宽了什么。只收紧访问的更改会立即保存。FoxAuth 控制台本身永远不受这些条件限制，因此规则不会把您挡在控制台之外。

## 升级与回滚 {#rollback}

第一个带条件的版本会标记数据库，使更早的版本拒绝在其上启动。更早的版本无法执行条件，因此不能运行。第一个支持代理处验证码的版本会出于同样的原因再次标记数据库，第一个支持网络信息的版本也是如此。您无法回滚到此版本之前。在滚动部署期间，仍在运行的旧进程会对带条件的应用或 API 返回错误，直到被替换。它永远不会放行请求。
