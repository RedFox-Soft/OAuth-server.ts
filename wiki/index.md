# Wiki Index

The catalog of all pages in this wiki. Each entry: a wikilink to the page and a one-line summary. The LLM reads this first when answering queries to identify candidate pages.

Keep summaries tight — one line each. The index is engineered to be cheap to read; a fat index defeats its purpose.

When this file exceeds ~300 lines or the wiki passes ~150 pages, shard into `wiki/indexes/<type>.md` and replace this file with a directory of shards. See the `scaling-playbook.md` reference in the `llm-wiki` skill for the migration procedure.

## Concepts

- [[account-resolution]] — `findAccount` is a direct-import DB resolver, not a config option; enforces active status at every resolution and merges claims from the user record.
- [[admin-audit-trail]] — audit-first *and* authorization-first, in that order and inside the handler; a load-bearing route table; field names never values, and only the names that actually changed; Elysia strips undeclared query params before validation.
- [[admin-provisioning]] — the console's records are seeded by `db:setup`/`db:setup:pg`, never at boot; the values are declared once in `admin_seed.ts` so a change cannot land in the seeder production never runs; re-run after an upgrade.
- [[per-issuer-isolation]] — declared resources are unique per issuer and each addressable bucket signs with keys of its own; the root namespace is super-admin only because metadata cannot name a root tenant; the no-transition key switch and the 30 s TTL rotation is built on.
- [[group-ownership]] — a group owns every project and bucket and is the only thing that grants access; owner-vs-member is a property of a membership, not a role; the active scope lives on the session and is re-validated per request; a refusal must not reveal existence; the retired `managedBy` migration grouped by identical manager set so two tenants sharing one manager were never merged.
- [[container-ownership-transfer]] — a bucket moves to another group with every project using it, as one change; owner of the group it leaves, member of the one it joins; a repeated move completes a half-done one; bucket-first on a standalone `mongod`; the bind route's post-write check; one audit entry both groups read; the migration that made personal groups single-member.
- [[admin-console-signin]] — the console is a relying party on its own issuer and must verify the ID token; the advertised alg list contains `HS256` and is a boot snapshot, `assertPayload` skips future-`iat` whenever `exp` is present, and no `azp` is ever emitted.
- [[admin-mcp-control-plane]] — an agent administers the instance by re-dispatching into the real admin routes, so there is no second implementation; a load-bearing tool catalogue, the audience boundary in both directions, two withheld deletions, and four traps (flat `id` collision, closed schema vs open-map body, Elysia eating the body, the model-graph lazy import).
- [[mcp-server-authorization]] — the server as an authorization server for *other* MCP servers: a declared resource is data read every time, five bucket-resolution rules whose third one answers D6 (and which every caller must pass the resource to), a `client_id` that is a URL and stores nothing, the administrative allowlist with its loopback interlock, and four things that cannot be done the obvious way — the branch order in `tryFindClient`, dot segments on a parsed URL, an expiry index on the `Client` area, and restricting a permitted redirect target.
- [[admin-plane-error-shape]] — the admin plane answers `{ error: 'admin_error', message }`; the root OAuth handler is registered first and silently replaced it with `server_error` in the composed app, which every standalone-mounted admin spec missed.
- [[client-identity-from-database]] — `adapter('Client')` is the single source of client identity; the adapter is read every call and the LRU memo caches only validated objects, keyed by property hash.
- [[client-registration-attributes]] — every rule the registration validator applies to an attribute lives on its one entry; declaration order is the stored key order, two precedence lists decide which refusal a two-rule violation gets, and the structural layer stays in `ClientSchema` on purpose.
- [[bucket-is-an-issuer]] — a bucket is addressed in the URL and is its own issuer; the default bucket keeps the bare one, the two reserved buckets are not addressable, and a token records which bucket minted it. Since 056 the address is a path segment **or** a hostname and never both, resolved through one derived `addressOf` with a fourth `unaddressed` state that exists because the issuer and the cookie fall back differently.
- [[cookie-path-scoping]] — `(name, domain, path)` identifies a cookie, so `remove()` — which takes its `Path` from the route's schema (`/` in practice), never from the cookie — clears a different cookie than the one the browser keeps sending.
- [[typebox-dual-type-resolution]] — `tsc` resolves TypeBox to CommonJS declarations for Elysia and ES module ones for this repository, so schemas and TypeBox errors crossing to Elysia fail to type-check; meet Elysia on shape, and never force one set through `tsconfig` `paths`, which Bun honours at runtime.
- [[remember-me-session-retention]] — the "Remember me" checkbox was decorative for the life of the product: four independent breaks on one path, each sufficient alone; `transient` is the negative and absent means remembered; omitting `expires` works because `set()` resets from the schema's attributes; two tests were named for the distinction while proving nothing about it.
- [[single-use-under-concurrency]] — a code, a rotating refresh token, a pushed request and a replayed `jti` are single use because `consume` answers whether *this* call spent the record and `create` stores only when the id is free; until 2026-09-29 each decided on a copy read earlier, so parallel requests all won.
- [[interaction-browser-binding]] — the uid is in every URL and is no secret; the `_interaction` cookie's value (`cookieID`) is what binds a sign-in to its browser, and from `53341c6` until 2026-09-28 it was read and never compared, which let a uid holder take over a second-factor enrolment.
- [[cross-site-sign-out-post]] — `POST /logout` is not the GET mounted twice: a relying party's sign-out form is cross-site, `Lax` withholds the session cookie, and handled bare it overwrites the sign-in with an empty session and says "signed out"; it is bounced once through a same-origin form instead.
- [[end-user-cookie-attributes]] — a cookie's attributes come from whichever route's schema is running, so the weakest schema naming a cookie decides what the browser stores; two schemas named `_session` and the `/ui` one carried no attributes at all.
- [[end-user-lifecycle]] — deactivation, the local lock and deletion end access at once (back-channel logout, then the account-owned sweep); provisioned users are read-only locally; username/externalId uniqueness rides on derived scalar keys; profile → claims table; an address change is refused before audit when taken, and a verification message proves only the address it reached; `passwordSet` says whether a chosen password opens the account.
- [[deletion-and-revocation]] — revoke, cascade and guard are three different operations; ownership is declared per storage area and read by one engine; two areas no grant walk reaches.
- [[bucket-groups]] — roles are gone: end users are grouped by bucket groups (members as records, not a list, after checking that no directory caps a group; every refusal decided before the first write, one transaction except on a standalone `mongod`), relying parties read them from a built-in `groups` claim (display names, a userinfo reference above 200), SCIM serves `/Groups`, and the administrators' `super_admin` is membership of the reserved Super administrators group.
- [[global-token-revocation]] — a bucket's upstream provider (Okta Universal Logout) ends everything a user holds here with one signed request; built on an expired individual draft behind an off-by-default flag, as one format over a format-neutral core whose refusals no setting can relax (Keycloak CVE-2026-18569); a second, cooldown-keeping key cache for presented JWTs; audited under the new "sign out everywhere".
- [[upstream-back-channel-logout]] — a bucket receives OIDC Back-Channel Logout from Keycloak, Auth0 and Ping and ends the sessions that came from the named upstream session (or, for a `sub`-only token, that person's sessions from that provider), keeping offline access; a session now records its upstream origin (provider + digest of `sid`) and an `UpstreamSession` record maps an upstream session to its account; the core learned where each format carries our client id; 400 for every refusal and fault, the fault still recorded (fifth capture site).
- [[scim-provisioning]] — a bucket provisioned by an enterprise directory over SCIM 2.0 through a provisioning connection: a never-stored `scim-<id>` client with a hashed secret, a built-in per-bucket resource arm ahead of MCP's, opaque tokens, its own errors, parser and per-connection limiter, own filter/patch code instead of the libraries the issue named, a correlation step that ends the federation ladder, and the three deviation settings with why each defaults as it does.
- [[scim-credential-overlap]] — replacing a SCIM connection's client secret or static token keeps the old value working until the directory has used the new one and gone an hour without the old, 24 h at most, because Entra's and Okta's connection tests use the new value before Save; tokens carry `credentialRef`, so an administrator's retire/stop/revoke sweeps only the old value's tokens and an end by itself sweeps nothing; keys and kind changes replace at once; static tokens expire (90 days or a year, RFC 7644 §7.4) with a backfill migration.
- [[end-user-onboarding]] — registration and email verification are per bucket; the door resolves on GET as well as POST, a correct password for an unverified account is sent what it needs, the sign-in page links only to open doors, codes are hashed and capped, an administrator's create follows the bucket's verification policy, and SMTP is read live from its own store, not from `ApplicationConfig`.
- [[bucket-workspace]] — a bucket opens on an Overview (needs attention, issuer and discovery to copy, sign-in at a glance, counts from a summary using `tally()`) and keeps name, address, ownership and a Danger zone on Settings; `changeAddress`/`delete` became state-aware (an owner changes an unused path; only owners delete a bucket holding accounts); address change previews by name and commits with `expect`; host arrivals clear on an address change.
- [[bucket-soft-delete]] — since spec 090 deleting a bucket schedules its destruction 30 days out: every door at its address answers as absent, the default `findAccount` refuses its tokens anywhere else, nothing in it is destroyed, and Restore brings it back with sessions intact; one guard keyed on the mounted route pattern refuses every admin write and tells strangers nothing; `destroyBucket` (Delete now and the hourly pass) is claimed, recorded once as the admin or `system:retention`, and destroys the bucket record last so a failure is finished by the next pass; address caches expire after 60 s so every instance converges.
- [[bucket-users-workspace]] — the Users tab reads one server page at a time with search and filters in the address; each person has a page (Profile, Sign-in methods, Groups, Activity) with acts at their confirmation class; no save spans two requests; the group member picker searches the server; account components shared with phase 4.
- [[end-user-support]] — since spec 089: an invitation is a password-reset challenge with `purpose: 'invite'` and 7 days (and the reuse fixed a reset link that survived an email change, and a 24 h supersession pointer); mark verified is a named act; sessions are read from grants and per-app sign-out never extends the session; local users get the directory's profile shape, and the profile now wins over stored claims; four bulk routes write one audit entry per person; member search reuses the prefix search through `memberOf`.
- [[console-federation]] — administrators sign in through the administrators' bucket's providers: super administrators configure them; there every link needs the password proof and a closed sign-up closes creation (a created administrator gets a personal group, never the privilege); passwords go off only from a session that came in through a linked provider, one reachability predicate refuses every change that would shut the console, `admin:password-sign-in` is the server-side way back; agent writes there are high-consequence via `highWhen`.
- [[admin-console-frame]] — every console screen has an address (one route table for the server's 404 and the client router; sign-in returns via a twice-validated `next`); bucket and project responses state `can`, which the routes decide through, so the console hides what it may not do and disables with a reason what state blocks; one C0–C4 confirmation table; feedback only through antd `App` (static `message`/`Modal` are lint errors); the admin 422 no longer echoes the submission.
- [[bucket-sign-in-policy]] — a bucket PATCH decides rights, then refusals (no way in; verification without mail on every bucket; the console bucket's guards), then a counted preview for any change that tightens sign-in, applied only with `confirm` and the same `expect`; the tally's `withoutEnabledLink` and `passwordWithoutAuthenticator`; new buckets closed; signing an administrator out and resetting their authenticator.
- [[provider-connection-group-pages]] — spec 084: a page each for providers, provisioning connections and user groups; wizards whose last step (who a first sign-in creates; the deprovisioning safeguard) has no default; trust-widening saves asked by name; the hold panel listing refused removals; `SecretReveal`; the group hand-over as C4.
- [[admin-bucket-settings]] — the administrators' bucket is edited on the ordinary bucket settings through a narrow loader, never by opening the shared ones; a guard per setting (verification needs mail and your own address proven) instead of a blanket refusal; administrator sign-up with a personal group; federation into the console is a separate feature.
- [[monthly-active-users]] — every bucket counts the distinct people it issued tokens to, per UTC month and day: one recording site in `executeGrant` (a call, not a listener), the bucket `findAccount` resolved rather than the token's root-served `bucketId`, the kind on the artifact because a sign-in followed by consent sits in `lastSubmission`, marks counted at read instead of counters (exact, no transaction), insert-if-absent freezing with a five-minute grace, unowned areas so deletions keep the history, and the deferred list of who.
- [[error-store-capture-sites]] — recorded faults are captured in seven places: two because the global handler stands aside on the `adminPlane` *marker* and only a deliberate `AdminError` carries one, the third because a fault delivered to a client by redirect returns before the handler records it (filed at 500, no reference in the URL), the fourth SCIM's own handler, the fifth the upstream back-channel logout receiver, which must answer a fault 400, the sixth the device-flow completion, the seventh the activity recorder, whose request succeeded; `set.status` may be a status name, so an un-narrowed `>= 500` test silently records nothing.
- [[interaction-error-delivery]] — every error that ends an authorization request, at `/auth` or after the interaction pages, is delivered to the client by one module; on resume the boundary is the restored request, not a list of errors, which keeps untrusted-interaction failures on-page by construction; the client and redirect URI are re-checked at delivery, for a code as much as an error; consent refusal is an interaction result, not a throw.
- [[untrusted-redirect-confirmation]] — an authorization error for a client whose redirect URIs no operator vouched for (self-registered, or from a metadata document) is offered on a confirmation page instead of redirected, per RFC 9700 §4.11.2 as its editors read it; trust is provenance, not id shape; one answer description feeds both the redirect and the page; the page denies framing despite its off-origin form.
- [[error-store-is-not-flag-gated]] — the admin operation set is invariant under capability switches, guarded twice; gating an admin route also splits the console from the agent surface, which re-dispatches without the gate plugin — so the flag is reported in the payload and the agent purge is withheld outright rather than opt-in.
- [[feature-flag-gating]] — flat dotted keys on `ApplicationConfig`, an overrides document holding only edited keys, a derived `configuration` re-derived in place whenever a save is applied, and the `onRequest` gate that makes a disabled endpoint answer as unserved.
- [[first-run-setup-had-two-surfaces]] — `GET /admin` is the only bootstrap surface; the deleted `/admin/setup` twin pointed at an unserved bundle and rendered a blank page nothing linked to.
- [[html-response-security-policy]] — one constructor builds every HTML response and hashes its own inline scripts; a global lifecycle plugin was measured and misses the error page and the named admin instance.
- [[non-html-response-hardening]] — the companion policy for everything that is not a page, written from one `onRequest` hook; there is deliberately no page-detection branch because a page's own `Response` header wins over the merge, the CORS mount-order caveat does not bind a pre-routing hook, and the single-writer guard is a substring scan a comment can fail.
- [[interaction-page-families]] — every end-user screen is either the hydrated antd shell or a plain self-contained page; a hydrated page without props erases its own server-rendered message, silently and only in a browser; antd's `zeroRuntime` never reaches zero because a second, ungated hook always injects a small cssVar block.
- [[model-graph-import-order]] — `lib/models/` has a cycle, so a cold entry throws a TDZ `ReferenceError`; enter through `test_helper` first, and the existing drift guard only passes by accident.
- [[mongodb-test-fidelity]] — the production backend carried zero coverage by constitutional rule, until the rule shipped a server that could not boot; two tiers now, split on whether a property can be proven without a server, and three import-time barriers in the way.
- [[test-admission-rule]] — a test proves a user case or a security invariant, or it is deleted; the guards were never structure tests because they enumerate the mounted route table, the templates are two because a completeness guard has no trigger, and a change-detector can sit inside a real guard — which is why classification runs per case, not per file.
- [[spec-file-isolation]] — nothing reaches from one spec file into the next: the preload restores spies, the clock and the environment at the boundary, marked by a resolver that watches the next spec file resolve, and `bootstrap()` replaces every store and forgets every cache built from one; reset rather than detected, because Bun cannot list its spies and at the boundary nothing may want the leftovers; case order inside a file is still `--randomize`'s to show.
- [[postgresql-backend]] — a second datastore behind the same contract; two expiry designs reversed by reading the call sites, a tolerant decoder that hid a jsonb encoding defect for a commit, why the fidelity checks are scripts, the migration layer's four states and its `rerunnable` sentence, the liveness/readiness split the lazy handle forced, and the `text_pattern_ops` prefix indexes the users search needs (MongoDB builds none).
- [[per-origin-rate-limiting]] — mounting before the feature gate is a correctness call, not an optimisation; the refusal renders at the root because the throw precedes routing; counters are bounded, in-process and never persisted, which makes it a resource protection rather than a security boundary.
- [[override-seams-vs-dead-code]] — an empty addon body is an extension point's default, not an abandoned stub; source modules import the accessor rather than the implementation, so an importer census reports live seams as dead, and resolving a removal candidate by symbol name instead of path nearly deleted a live `urlFor`.
- [[pairwise-identifier-salt]] — the pseudonym is a relying party's account key, so its salt is stored server state, never the hostname; an unusable salt fails closed at the token endpoint and is never replaced, and the logout notification derives its `sub` a layer away in the claim pipeline.
- [[form-action-redirect-chain]] — a browser checks form-action against every hop of a submission's redirect chain, so `'self'` blocked the hand-off to a foreign callback after the code had already been issued; only a real browser can see it.
- [[first-consent-grant-id]] — an interaction's grantId is a hint, not proof of storage; a first consent resolved it with find() and answered 401 invalid_token for a missing record, and the harness's pre-seeded grant hid the branch.
- [[login-door-throttle]] — the second factor's failure window moved to the password door; two horizons whose confusion silently removes the escalation, a ceiling that reads the bucket's second factor rather than its id, the reset flow as the escape hatch, and a casing bypass that passes every lower-case test.
- [[loopback-redirect-port-matching]] — a native client's loopback redirect may differ from its registration in the port alone; registration-time validation knew this shape and request-time matching did not.
- [[pkce-verifier-length]] — the challenge is 43 characters because it is a digest; the verifier is 43..128 because the client chose, and pinning it at 43 refused conformant clients at schema validation with a 422, three steps upstream of the 401 they saw.
- [[self-service-password-reset]] — a reset secret is hashed at rest, expiry-checked in code because Mongo's TTL monitor is lazy, never consumed by a GET, and refused for the reserved admin bucket; one accepted page for every outcome.
- [[upstream-federation]] — a bucket may accept sign-in through external OIDC providers; the flow is three hops because the interaction cookie provably cannot survive the trip to an upstream, both round-trip records are keyed by a digest of the value they never store, and linking to an existing account needs operator trust *and* a verified assertion.
- [[federation-try-signin]] — an administrator tries a provider through the bucket's real callback and sees the provider's answer and what a real sign-in would do, with nothing written: the ladder split into reads-only `decideFederatedAccount` and `applyDecision`, a try decided only by the stored record, bound to a digest of the console session cookie (RFC 9700 §2.1.1), read by polling because the Strict console cookie cannot survive the return from the provider; works on a disabled provider; excluded from MCP as inapplicable.
- [[recognised-provider-divergences]] — why Microsoft, Apple and GitHub each needed more than a catalogue row: a templated issuer no equality check can satisfy, a credential that expires in six months so it is minted per exchange, and a provider that asserts no identity at all — plus the finding that three of four providers were silently getting no PKCE because support was inferred from metadata that under-reports it.
- [[rich-authorization-requests]] — `authorization_details` end to end on the code and refresh flows; the declared parameter schema is a runtime coercion contract, and details reach a token only when a resource server resolves.
- [[refresh-token-chain-bound]] — a browser application's rotated refresh tokens inherit the chain's remaining lifetime, decided from `iiat`/`rotations` on the token itself; dead from `54ba556` until 060, masked by the equal default grant lifetime.
- [[stored-document-schemas]] — every store document type is a TypeBox schema, and every PostgreSQL/MongoDB read is checked against it: dates and Mongo's `undefined`-as-null translated back by the schema, a mismatch thrown as a defect rather than read as missing.
- [[token-payload-access-contract]] — model state lives under `.payload.*`; reading a bare field yields `undefined` silently, and payload schemas are composed per token type.
- [[two-meanings-of-origin]] — `origin` names the caller's network address on the record and the code location on the occurrence, so the outbound event carries both under different names and must never merge them; the location is sendable only because no stack is kept, the permitted list is enforced one level deep, and grouping cannot be disturbed because a client fingerprint suppresses the destination's algorithm entirely.
- [[authentication-context-reporting]] — the server owns which sign-ins it can tell apart and an operator owns their names, because context matching is exact string comparison; the advertised set is derived so it cannot overclaim; it was two gaps not one (a getter read past the payload, making an essential `acr` permanently unsatisfiable); the refusal is delivered from the resume route by the general rule ([[interaction-error-delivery]]); and the backchannel breaks the same invariant the other way — a token that should not exist rather than a loop.
- [[amr-reporting]] — every ID token from a sign-in states its methods (`pwd`; `pwd`+`otp`+`mfa`; none when federated), keyed on the same distinctions as `acr`; declaring the claim was never enough because it must also be requested, so it is written past the mask like `sid` and advertised whatever the stored claims setting says; never fails a request; forwarding a trusted provider's `amr` is deferred with its cost written down.
- [[totp-second-factor]] — one bucket boolean turns a password door into a two-key one; the algorithm is in-repo because the RFCs publish test vectors, and four placements of state buy deletion integrity, expiry, un-guessable enrolment and a throttle that survives a new interaction for free.
- [[settings-console-descriptor]] — the console's panes, summaries, units, risk marks and now the restart class are fields on the catalog descriptor, so the page holds no second list of settings; the demotion criterion is "is there a question an operator could answer to set it", a key's absence from the catalog removes it from both the console and the agent surface, and a saved setting is in force without a restart unless its descriptor says otherwise.
- [[signing-keys]] — every issuer's keys, the root's included (owner `'#root'`), are `bucketKeys` records with one lifecycle: generate (published) → promote after the window (one signer per algorithm) → retire with a typed-kid confirmation → hidden after a day, never deleted; no restart; the leaf `keystore.ts` is a mirror of the root's signing and encryption keys.
- [[user-code-mask-entropy]] — the asterisks in `deviceFlow.mask` are the whole of a user code's entropy, so a mask with none issued the same code to every device and passed a character check that never asked for shape; the floor is zero-vs-nonzero because how many is enough is an operator's judgement, and the check is scoped to the flow being enabled without leaving a hole.
- [[security-assurance-evidence]] — SECURITY.md was policy without proof; now a threat model (RFC 9700 shape, every control row names its source and its spec, and the Known limitations are the evidence), an assurance page that says what has not been done, and a Security workflow (CodeQL incl. `actions`, `bun audit` on both lockfiles, dependency review, Trivy to code scanning) plus Scorecard and Dependabot; the image scan deliberately does not fail the build, actions stay on major tags for now.
- [[unknown-request-parameters]] — six endpoints must ignore a parameter they do not define (RFC 6749 §3.1 *and* §3.2, RFC 8628, CIBA, RFC 9126 by reference, RFC 9101 for the Request Object); once absence means "ignore", every deliberate refusal has to be declared as `t.Undefined` or it silently becomes acceptance; `normalize: true` is the wrong instrument because it also cleans headers and breaks mTLS-bound tokens, and it cannot reach the Request Object at all.
- [[site-translations]] — foxauth.dev in Russian and Simplified Chinese for readers whose browser puts that language first, and nobody else: an inline head script on a static host (redirect to the page's own `hreflang` *path*, never for crawlers or from a translation just left), Starlight fallbacks kept and canonicalised to the English page (not `noindex`), one release for both languages with unpublished directories left out of the collections, source hashes not git dates, explicit heading ids checked by `counterpart-anchor`, Chinese SEO bands and `keep-all` buttons.
