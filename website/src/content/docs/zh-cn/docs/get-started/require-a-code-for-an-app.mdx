有些应用比其他应用更重要。账单应用或管理工具不应该向只知道密码的人开放。本页介绍如何让一个应用要求身份验证器应用中的验证码，同时不改变项目中的其他应用。

## 开启 {#on}

1. 在控制台中打开该应用的 **Settings** 选项卡。
2. 打开 **Require a code from an authenticator app** 并保存。
3. 在任何更改生效之前，控制台会显示这会影响哪些人：
   - 使用密码登录但没有身份验证器应用的人。系统会要求他们先设置一个；如果您的项目不允许用户自行设置，他们将被拒绝；
   - 只能通过身份提供方登录的人。他们将被拒绝；
   - 当前持有该应用登录的人。
4. 确认。列表中该应用一行会显示 **Code required**。

代理可以通过 `client_update`（`requireCode`）完成同样的操作。这是高影响的更改，代理会收到相同的数字以供确认。

## 用户看到什么 {#person}

每次登录只要求一次验证码，而不是每次打开应用都要。

- **已有验证码。** 用户输入密码，然后输入验证码。已经用验证码登录的人不会再被询问。
- **没有验证码。** 输入密码后，页面会说明该应用需要身份验证器应用中的验证码。用户可以选择 **设置身份验证器应用**：FoxAuth 会通过电子邮件发送一个链接，用户在同一浏览器中打开它，扫描二维码并输入验证码。**继续** 会在同一次登录中带他们进入应用。
- **您的项目不允许用户自行设置。** 页面会如实说明，并请他们联系您。
- **通过身份提供方登录。** 页面会显示身份提供方的名称，并说明这种登录方式无法打开此应用。如果账号还有密码，页面会提供 **改用密码登录**。

每个版本的页面都有 **不登录，返回应用**。此时应用会收到错误 `unmet_authentication_requirements`。请确保应用为它显示一个有帮助的页面。

<Aside type="caution">
	开启此设置后，只能通过身份提供方登录的人无法打开该应用。确认之前，请查看控制台显示的人数。
</Aside>

## 令牌 {#tokens}

- 已经完成的登录在应用刷新令牌之前继续有效。之后，没有验证码的登录所得的刷新令牌会失效，用户需要重新登录并输入验证码。
- 同样的规则适用于设备登录和 CIBA。
- 断言授权（JWT bearer 和身份断言）会被拒绝，因为在这里没有输入验证码。令牌交换只有在其背后的登录包含验证码时才有效。
- client credentials 令牌不代表任何人，因此不受影响。
- 没有“验证码须在 N 小时内”的规则。只要是带验证码的登录，无论多久以前都可以。

## 只在部分页面要求验证码 {#some-pages}

保持开关关闭，在需要的地方要求验证码。发送 `acr_values`，值为您服务器的多因素值（应用的 **Connect** 选项卡会显示它），并检查 ID 令牌中的 `acr`。在 IPSIE SL1 配置文件下或使用必需的 `acr` 声明时，该请求是强制的。否则它只是一个请求，因此应用必须检查 ID 令牌。

## 回滚 {#rollback}

`db:migrate` 会记录一个迁移，之后旧版本将拒绝在该数据库上启动。旧版本不了解此设置，会让没有验证码的人登录。
