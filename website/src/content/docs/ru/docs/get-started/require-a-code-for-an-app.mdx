Одни приложения важнее других. Биллинг или админка не должны открываться тому, кто узнал только пароль. Эта страница
описывает, как потребовать код из приложения-аутентификатора в одном приложении и не трогать остальные приложения
проекта.

## Как включить {#on}

1. Откройте приложение в консоли, вкладку **Settings**.
2. Включите **Require a code from an authenticator app** и сохраните.
3. Прежде чем что-то изменится, консоль покажет, кого это коснётся:
   - людей, которые входят по паролю и не настроили приложение-аутентификатор. Их попросят его настроить. Если проект
     не разрешает настраивать его самостоятельно, их не пустят;
   - людей, которые могут войти только через провайдера. Их не пустят;
   - людей, которые сейчас вошли в это приложение.
4. Подтвердите. В списке у приложения появится метка **Code required**.

Агент делает то же через `client_update` (`requireCode`). Это изменение с высоким риском, и агент получает те же числа
для подтверждения.

## Что видит человек {#person}

Код спрашивается один раз за вход, а не при каждом открытии приложения.

- **Код у человека есть.** Он вводит пароль, затем код. Того, кто уже вошёл с кодом, ни о чём не спрашивают.
- **Кода нет.** После пароля страница сообщает, что приложение просит код из приложения-аутентификатора. Человек может
  выбрать **Настроить приложение-аутентификатор**: FoxAuth пришлёт ссылку на почту, человек откроет её в этом же
  браузере, отсканирует QR-код и введёт код. Кнопка **Продолжить** приведёт его в приложение в рамках того же входа.
- **Проект не разрешает настраивать код самостоятельно.** Страница так и говорит и предлагает обратиться к вам.
- **Человек вошёл через провайдера.** Страница называет провайдера и объясняет, что так в приложение не войти. Если у
  аккаунта есть и пароль, она предлагает **Войти с паролем**.

На любом варианте страницы есть **Вернуться в приложение без входа**. Тогда приложение получит ошибку
`unmet_authentication_requirements`. Проверьте, что приложение показывает для неё понятную страницу.

<Aside type="caution">
	Кто входит только через провайдера, не сможет открыть приложение, пока
	настройка включена. Посмотрите на число в консоли, прежде чем подтверждать.
</Aside>

## Токены {#tokens}

- Уже выполненные входы работают, пока приложение не обновит токены. После этого токен обновления от входа без кода
  перестаёт работать, и человек входит заново, уже с кодом.
- То же правило действует для входа с устройства и для CIBA.
- Гранты по утверждениям (JWT bearer и утверждения о личности) отклоняются, потому что здесь кода никто не вводил.
  Обмен токена работает, только если за ним стоит вход с кодом.
- Токен client credentials действует не от имени человека, поэтому его это не касается.
- Правила «код не старше N часов» нет. Достаточно входа с кодом, даже давнего.

## Код только на некоторых страницах {#some-pages}

Оставьте переключатель выключенным и запрашивайте код там, где он нужен. Отправьте `acr_values` со значением
двухфакторного входа вашего сервера (его показывает вкладка **Connect** приложения) и проверьте `acr` в ID-токене. По
профилю IPSIE SL1 или с обязательным claim `acr` запрос обязателен. Иначе это только просьба, поэтому приложение должно
проверять ID-токен.

## Откат {#rollback}

`db:migrate` записывает миграцию, после которой более старый релиз не запустится на этой базе. Старый релиз не знает
эту настройку и пустил бы людей без кода.
