Auth0 is a managed service. That is the difference every other row follows from: you do not
operate it, and you do not choose which parts of it you run.

The rows below are what its own documentation says, on the date in the banner above. Where a page
did not answer the question, the row says "not documented" rather than guessing.

## Side by side

| Dimension                                 | FoxAuth (OAuth-server.ts)                                                                                                             | Auth0                                                                                                                                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hosting model                             | Self-hosted. Container image `ghcr.io/redfox-soft/oauth-server-ts`, or importable as a library.                                       | Managed. A multi-tenant public cloud, or Private Cloud on AWS or Azure described as "A dedicated, managed cloud service". Self-hosting on your own infrastructure is not documented.          |
| Language / runtime                        | TypeScript on Bun; the HTTP layer is Elysia. The whole server is code you can read and fork.                                          | Not applicable — the runtime is Auth0's. Customisation is through Actions rather than through the server itself.                                                                              |
| Admin UI                                  | Built-in console for projects, clients, administrators, user buckets, end-users, upstream providers, settings, SMTP and signing keys. | The Auth0 Dashboard. The Management API docs note that "anything that can be done through the Auth0 Dashboard can also be done through this API".                                             |
| Admin API for agents (MCP)                | 60 MCP tools served by the server itself at `POST /mcp`, with RFC 9728 metadata and two-call confirmation. Off until `mcp.enabled`.   | An Auth0 MCP Server is documented; it "connects AI agents to your Auth0 tenant", calls the Management API, and authenticates with the "OAuth 2.0 Device Authorization Flow".                  |
| OAuth 2.1 defaults (PKCE for all clients) | PKCE is mandatory for every client, public or confidential. A requirement for every client is not documented.               |

| PAR                                       | RFC 9126, behind `par.enabled`.                                                                                                       | Supported, based on RFC 9126. | FAPI                                      | FAPI profile behaviours behind `fapi.enabled`. | CIBA                                      | Behind `ciba.enabled`.                                                                                                                | Supported: "you must have an Enterprise Plan or an appropriate add-on". | mTLS                                      | RFC 8705 client authentication and certificate-bound tokens, behind `mTLS.enabled`.                                                   | mTLS for OAuth is part of Highly Regulated Identity, on the Enterprise Plan with that add-on.                                                                                                 |

## Where each one fits

**Auth0 is the safer default if** you do not want to run a database, you need social and enterprise
connections working this week, you want certified FAPI conformance you can hand to a reviewer, or
your identity budget is smaller than the cost of an engineer keeping a server healthy.

**FoxAuth is the better fit if** your cost grows with your user count and you would rather it grew
with your infrastructure, if a regulator or a contract requires the data to stay in your own
database, if you need the banking-grade profiles without an Enterprise add-on, or if you want an AI
agent administering the instance through the same audited path a human uses.

The honest asymmetry: Auth0 is a product with a support organisation, a status page and years of
certifications. FoxAuth is a server at version 0.x. If you cannot operate a database and a
container, choose the managed service — ours is not ready.

## Migrating

Auth0 can export users and clients, and its Management API can list both. FoxAuth clients are then
created through the admin API or dynamic registration, and users through a user bucket. Password
hashes are not portable, so plan a reset-on-first-login window.
