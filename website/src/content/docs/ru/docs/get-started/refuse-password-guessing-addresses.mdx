У кого есть утёкший список паролей, тот пробует его на ваших учётных записях с одного адреса, сразу на многих. Троттлинг
входа считает неверные пароли для каждой учётной записи отдельно. Поэтому адрес, который пробует каждую запись всего
несколько раз, троттлинг не останавливает. Эта страница показывает, как проект может отказывать во входе по паролю
адресам, которые известны таким подбором.

## Что в списке {#list}

FoxTrust работает как сервис репутации адресов и получает отчёты FoxAuth об атаках. Он публикует список адресов, с
которых, по его данным, подбирали пароли за последние 7 дней. Список пересобирается каждый час и подписывается.

- Сейчас в списке около 3 000 адресов. Большая часть получена из сторонних источников.
- FoxTrust никогда не вносит адрес в список только по отчётам одного сервера.
- Запись IPv4 означает один адрес. Запись IPv6 означает сеть /64, то есть все адреса этой сети.

В общем списке есть общие адреса: мобильного оператора, офиса, общественного Wi-Fi. Поэтому каждый проект сначала
считает и отказывает, только когда это подтверждают его собственные числа.

## Что узнаёт FoxTrust {#privacy}

Ничего о тех, кто входит. Ваш сервер скачивает список и сам сверяет с ним каждый вход. При скачивании FoxTrust получает
название «FoxAuth», а пока включены отчёты об использовании, ещё и версию FoxAuth. Имя вашего сервера, адрес человека и
учётная запись не передаются.

Адрес человека, которому отказали, нигде не записывается: ни в журнал, ни в событие, ни в запись об ошибке, ни в журнал
аудита, ни в счётчик. Его видит только сам человек на своей странице.

## Как включить список {#turn-on}

Суперадминистратор открывает **Settings → Integrations** и в разделе **Attack reporting** включает **Use FoxTrust's
list of known password-guessing addresses**. По умолчанию переключатель выключен.

Для него должен быть включён **Report attacking addresses to FoxTrust**, потому что список строится из того, что
присылают серверы. Если потом выключить отчёты об атаках, консоль сначала спросит подтверждение и покажет, сколько
проектов считают или отказывают по списку. После подтверждения эти проекты никому не отказывают.

Дальше каждый процесс сервера:

1. скачивает список каждый час, вскоре после того, как FoxTrust его пересобирает, а также в течение минуты после
   включения;
2. проверяет подпись ключом, встроенным в FoxAuth, и отклоняет список, который старше уже полученного или у которого
   истёк срок;
3. использует список не дольше 3 часов после того, как FoxTrust его собрал.

Карточка под переключателем показывает, когда собран список, сколько в нём адресов, до какого времени он действует и
какое последнее скачивание было отклонено и почему.

## Решайте по режиму Count only {#count}

Каждый проект выбирает режим на вкладке **Sign-in**, в карточке **Password guessing from known addresses**:

| Режим                       | Что происходит                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| **Nothing**                 | Входы с адресов из списка не считаются и не отклоняются.                                          |
| **Count only**              | Режим по умолчанию, когда список включён. Ни для кого ничего не меняется. Проект считает.         |
| **Refuse password sign-in** | Адресу из списка, который продолжает ошибаться в пароле, отказывают, как описано [ниже](#refuse). |

Карточка показывает три числа за последние 7 дней:

- **Password sign-ins from listed addresses**: входы по паролю с адресов из списка;
- **Of those, with the right password**: из них с верным паролем;
- **Refused because of the list**: отказы из-за списка.

Оставьте проект на какое-то время в режиме Count only. Если много входов с адресов из списка были с верным паролем,
значит, ваши люди делят адреса со злоумышленниками, например за адресом офиса или мобильного оператора. Добавьте такие
сети в исключения, как описано [ниже](#exempt), и только потом включайте отказ. Если с верным паролем почти никого не
было, отказывать безопасно.

## Что делает Refuse password sign-in {#refuse}

Когда вы выбираете **Refuse password sign-in**, консоль ещё раз показывает числа проекта и просит подтверждения. Потом:

- Адресу из списка, который подбирал пароли в последние 48 часов, отказывают, когда он 3 раза ошибся в пароле на этом
  сервере в течение часа.
- Адресу, который FoxTrust подтвердил по независимым источникам, отказывают сразу, без этих 3 ошибок.
- Пока адрес продолжает попытки, ему продолжают отказывать. После часа без попыток у него снова 3 попытки.
- Человек с адреса из списка, который сразу вводит верный пароль, входит, как раньше.
- Попытку, в которой отказано, вообще не проверяют: пароль не сравнивают и учётную запись не ищут. Она не засчитывается
  в троттлинг самой учётной записи, поэтому злоумышленник не может так заблокировать её владельца.

Эти 3 ошибки считаются для всего сервера, а не для проекта. Адресу, который подбирает пароли в одном проекте, может
отказать другой проект, если в нём выбран отказ. Если у сервера несколько процессов, каждый процесс считает сам.

Затронут только вход по паролю. Вход через провайдера удостоверений, сброс пароля, регистрация и конечные точки выдачи
токенов не затронуты. Для проекта администраторов **Refuse password sign-in** не предлагается: так можно было бы
закрыть консоль для всех администраторов.

## Что видит человек, которому отказали {#refused-page}

Вместо формы пароля человек видит короткое объяснение на своём языке (английском, русском или китайском):

1. **Вход по паролю из этой сети сейчас недоступен.**
2. Что случилось: с адреса этой сети недавно подбирали пароли.
3. Что делать сейчас: попробовать войти из другой сети, например через мобильный интернет вместо Wi-Fi, или выбрать
   другой способ входа на этой странице. Кнопки провайдеров удостоверений проекта остаются.
4. Строку для тех, кто обслуживает сервис, с его собственным адресом и временем UTC:

   ```text
   listed-address · 203.0.113.7 · 2026-11-09 19:58 UTC
   ```

5. Последней идёт ссылка **Попросить FoxTrust проверить этот адрес**.

Страница одинакова при любом введённом email и не зависит от того, существует ли учётная запись.

## Как помочь человеку, которому отказали {#help}

Когда вам присылают такую строку, добавьте адрес из неё в **Never check these networks** на вкладке **Sign-in**
проекта. Человек сразу сможет войти снова. Адрес нигде не записывается, поэтому взять его можно только из этой строки.

## Never check these networks {#exempt}

Проект может перечислить адреса или диапазоны, которые никогда не сверяются со списком, например офис или выходной адрес
VPN. У каждого можно указать дату окончания. После неё список снова действует на этот адрес. Для адреса из исключений
ничего не считается.

- Пишите один адрес, например `203.0.113.7`, или диапазон, например `198.51.100.0/24`. IPv6 записывается так же.
- **Your address now** подставляет адрес, с которого вы работаете, чтобы исключить свою сеть в один шаг.
- В проекте не больше 100 исключений.

## Если адрес попал в список по ошибке {#dispute}

Попросите FoxTrust проверить адрес на его [странице спора](https://foxtrust.dev/dispute). Туда же ведёт ссылка на
странице отказа. Пока адрес не убран из списка, добавьте сеть в исключения, как описано [выше](#exempt).

## Если список устарел {#stale}

Если списка нет, если он старше 3 часов или записан в формате, который эта версия FoxAuth не умеет читать, никому не
отказывают. Каждый проект, который использует список, пишет об этом на вкладке Sign-in, например: «The list is out of
date, so nobody is refused because of it.» Так бывает, когда FoxTrust недоступен несколько часов. Защита возвращается
со следующим списком, подпись которого проверена.

<Aside type="note">
	Если на сервере неверно настроен адрес вызывающей стороны, каждый человек
	выглядит для него как адрес его собственного прокси. Адрес доверенного прокси
	никогда не сверяется со списком, поэтому такой сервер никому не отказывает, а
	не отказывает всем. Карточка отчётов об атаках предупреждает об этом.
</Aside>

## Для ИИ-агента {#agent}

Агент, подключённый к административной конечной точке MCP, делает то же самое через те же маршруты консоли и с тем же
журналом аудита: `attacker_list_status_get` читает состояние списка, `project_password_guessing_get` читает режим,
исключения и числа проекта, а `project_update` с полем `passwordGuessing` меняет их. Сам список включает настройка
сервера `attackerList.enabled`.
