У некоторых веб-приложений нет собственного входа. Это может быть панель мониторинга, внутренний инструмент или
админка, которую кто-то написал за один вечер. Открыть такое приложение может любой, кто знает адрес. Это можно
исправить, не трогая само приложение. Поставьте его за свой прокси, и пусть прокси спрашивает FoxAuth о каждом
запросе, прежде чем пропустить его к приложению.

Такой способ называется **forward auth**. Ваш обратный прокси (Caddy, Traefik или nginx) стоит перед приложением. О
каждом запросе он спрашивает ваш проект FoxAuth, можно ли пропустить этот запрос. Человека, который ещё не вошёл,
прокси отправляет на страницу входа проекта. Человека, которому можно открыть страницу, прокси пропускает и сообщает
приложению, кто это. Тот, кому нельзя, видит страницу с отказом.

Если прокси уже обслуживает приложение, на всё уйдёт около десяти минут.

<Aside
	type="note"
	title="Что нужно заранее"
>
	Работающий экземпляр сервера с учётной записью администратора ([Создание
	первого администратора](/ru/docs/get-started/first-admin/)), проект с людьми и
	хотя бы одна группа пользователей в нём. Приложение должно работать по `https`
	через прокси, который вы можете настроить.
</Aside>

## 1. Создайте приложение в консоли {#create-the-app}

1. Откройте проект, перейдите на вкладку **Applications** и нажмите **New application**.
2. Выберите **A web app with no sign-in of its own**.
3. Заполните четыре поля:
   - **Name**: так приложение называется в консоли.
   - **Address**: собственный адрес приложения по `https`, например `https://grafana.example.com`. Сохраняются
     только схема, хост и порт. Если вставить адрес с путём или параметрами запроса, форма их отбросит и скажет об
     этом.
   - **Who can open it**: одна или несколько групп. Открыть приложение могут только их участники. Отдельные части
     приложения можно открыть другим людям позже.
   - **Proxy**: Caddy, Traefik или nginx. От этого зависит только то, какую конфигурацию следующий шаг покажет
     первой.

Приложение появится в отдельной таблице на вкладке Applications. На его странице три раздела: **Connect**,
**Access** и **Settings**.

## 2. Настройте прокси {#configure-your-proxy}

В разделе **Connect** есть конфигурация для вашего прокси, в которую уже подставлены адрес проекта и идентификатор
приложения. Копируйте её оттуда. Примеры ниже содержат тот же текст, и строит его тот же код. Они показаны для
приложения по адресу `https://grafana.example.com` в проекте по адресу `https://auth.example.com/acme`. Вместо
`<appId>` будет идентификатор вашего приложения.

Каждая конфигурация делает три вещи:

- Сначала она отправляет каждый запрос на проверку по адресу `https://auth.example.com/acme/verify/<appId>`. Вместе с
  запросом передаются его исходные метод, хост и путь. Запрос, в котором нет хотя бы одного из трёх, проверка
  отклоняет.
- Она удаляет все заголовки `X-Auth-*`, которые прислал браузер. Так никто не сможет выдать себя за другого.
- Она передаёт запрос приложению вместе с заголовками из ответа проверки.

Считается, что само приложение слушает `127.0.0.1:8080`. Замените этот адрес на настоящий.

### Caddy {#caddy}

<ProxyRecipe kind="caddy" />

Блок `route` сохраняет порядок директив. Без него Caddy удалил бы заголовки `X-Auth-*` уже после того, как их
выставила проверка.

### Traefik {#traefik}

<ProxyRecipe kind="traefik" />

Это динамическая конфигурация для file provider. Параметр `authResponseHeadersRegex` удаляет все заголовки
`X-Auth-*`, которые прислал браузер, и копирует те, что вернула проверка. Параметр `preserveLocationHeader`
не даёт Traefik переписать адрес перенаправления на вход, поэтому оно ведёт в проект.

### nginx {#nginx}

<ProxyRecipe kind="nginx" />

Директива `auth_request` в nginx понимает только три ответа: можно, не выполнен вход и отказ. Поэтому у проверки
запрашивается только статус. Перенаправление на вход и страницу с отказом даёт второй запрос. Он выполняется для
страницы ошибки и для путей под `/_foxauth/`, которые относятся ко входу. Строки с сертификатом добавьте там, где
стоит комментарий.

## 3. Приложение должно быть доступно только через прокси {#reachable-only-through-the-proxy}

Проверка защищает только те запросы, которые проходят через ваш прокси. Запрос, который дошёл до приложения другим
путём, проверку пропускает. Тогда приложение поверит любому заголовку `X-Auth-*` в этом запросе.

Поэтому приложение должно слушать только там, куда может достучаться прокси: на `127.0.0.1`, в частной сети или за
правилом межсетевого экрана, которое пропускает только прокси. Раздел Connect напоминает об этом, потому что это
единственное, чего FoxAuth не может сделать за вас.

Если приложение умеет проверять подпись, оно может не зависеть от этого правила. Об этом ниже, в описании
`X-Auth-Assertion`.

## 4. Что получает приложение {#what-your-app-receives}

Когда запрос пропущен, прокси добавляет к нему такие заголовки:

| Заголовок          | Что в нём                                                                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `X-Auth-User`      | Идентификатор человека в проекте. Он никогда не меняется, поэтому узнавайте человека по нему.                                                                                  |
| `X-Auth-Email`     | Адрес электронной почты человека.                                                                                                                                              |
| `X-Auth-Groups`    | Идентификаторы групп человека через запятую. Сравнивайте именно их, а не названия групп: название может измениться.                                                            |
| `X-Auth-Assertion` | Те же сведения, подписанные ключом проекта. Это JWT, у которого аудитория (audience) равна адресу вашего приложения. Он действует 60 секунд. В нём есть и названия групп.      |
| `X-Auth-Reason`    | Короткий код решения, например `allowed`. Он есть и у отказов, например `not_in_group` или `no_session`, поэтому журнал доступа прокси показывает, почему человека не пустили. |

На пути, открытом для всех, первые четыре заголовка присутствуют, но пусты.

Приложение может проверить `X-Auth-Assertion` по ключам, которые проект публикует по адресу из своего `jwks_uri`.
Тогда оно знает, что сведения пришли от проекта. Ему больше не нужно верить, что каждый запрос прошёл через прокси.

## 5. Убедитесь, что всё работает {#check-that-it-works}

В разделе Connect четыре шага, и у каждого указано время, когда он впервые случился:

1. Приложение создано.
2. Прокси спросил этот проект о приложении.
3. Кто-то вошёл через прокси.
4. Кого-то пропустили.

Откройте приложение в приватном окне браузера. Вы должны попасть на страницу входа проекта, а после входа вернуться
на ту страницу, которую открывали. Если шаг 2 остаётся пустым, прокси не отправляет запрос на проверку. Если Connect
называет хост, который не совпадает с адресом приложения, прокси не передаёт исходный хост.

Чтобы выйти из приложения, откройте `/_foxauth/sign_out` на собственном адресе приложения.

## Кто открывает какую часть {#access-rules}

В разделе **Access** правила показаны деревом, по одному на путь. Правило говорит, кто может открыть этот путь и всё,
что под ним:

- участники одной или нескольких групп;
- все, кому проект разрешает вход;
- кто угодно, без входа (только для `GET` и `HEAD` и только для этого пути, если вы не открыли и всё, что под ним);
- никто.

Решает правило с самым длинным подходящим путём, поэтому порядок правил не важен. Правило для `/admin` действует и
для `/admin/users`, и для `/Admin/users`. Если после сохранения больше людей смогут открыть хоть какой-то путь,
консоль перечислит эти изменения и попросит подтвердить их. На той же вкладке есть проверка доступа: она говорит,
пустят ли человека по данному адресу сейчас и после сохранения.

Путь может требовать и большего, чем группа: только из вашей сети, только в ваши часы, только отдел или недавний
вход. Смотрите [Условия на вашем прокси](/ru/docs/get-started/add-conditions-at-your-proxy/).
