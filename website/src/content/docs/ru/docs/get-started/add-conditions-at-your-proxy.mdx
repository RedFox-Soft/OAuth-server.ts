Приложение за прокси решает, кто может открыть каждый путь. API, токены которого проверяет прокси, решает, какие
инструменты может вызвать токен. Об этом две страницы: [Вход перед веб-приложением](/ru/docs/get-started/put-sign-in-in-front-of-a-web-app/)
и [Защита MCP-сервера на вашем прокси](/ru/docs/get-started/protect-an-mcp-server-at-your-proxy/). Эта страница
добавляет к ним условия.

Условие означает «и только если». Оно никого не пускает сверх того, кого пускали раньше. Оно может только сузить
доступ.

## Какие бывают условия {#kinds}

| Условие                  | Что проверяет                                                   | Для чего        |
| ------------------------ | --------------------------------------------------------------- | --------------- |
| **From where**           | адрес входит в один из ваших диапазонов или ни в один из них    | приложения, API |
| **When**                 | момент попадает в ваши часы, в выбранном часовом поясе          | приложения, API |
| **Attribute**            | отдел, должность или другое поле человека равны одному из ваших | приложения, API |
| **Groups**               | человек состоит в одной из ваших групп                          | API             |
| **Ask to sign in again** | человек вошёл не раньше чем N минут назад                       | приложения      |

Группы приложения уже указаны в его правиле для каждого пути, поэтому условием они бывают только у API.

Значения внутри одного условия объединяются через «или»: «из офиса или через VPN». Разные условия объединяются через
«и»: «из офиса и в рабочие часы». У правила не больше одного условия каждого вида.

## Как условия действуют на пути {#paths}

Кто может открыть путь, по-прежнему решает самый длинный подходящий путь. Условия складываются вниз по путям:
условия `/` действуют на все пути, а условие на `/admin` действует на `/admin` и всё под ним, вместе с условиями `/`.
Путь может добавить условие. Убрать условие пути выше он не может. У публичных путей условий нет.

Проект решает в постоянном порядке:

1. **From where** и **When**, до входа. Человеку не из того места или не в те часы отказывают, не спрашивая пароль.
2. Вошёл ли человек, может ли он входить и состоит ли в группах правила.
3. **Attribute**.
4. **Ask to sign in again**, последним. Никого не отправляют входить, чтобы потом всё равно отказать.

## From where: прокси передаёт адрес {#from-where}

Адрес человека знает только ваш прокси. Браузер может записать в заголовок любой адрес, поэтому проект верит адресу,
только когда прокси доказывает, что записал его сам.

1. На странице **Connect** приложения или API откройте шаг **Your proxy passes people's addresses** и нажмите
   **Issue a proxy key**. Скопируйте ключ: он показывается один раз. У проекта не больше двух ключей, поэтому один
   можно заменить другим без момента, когда прокси получает отказ.
2. Добавьте в прокси строки из конфигурации на этой странице. Они перезаписывают `X-Forwarded-For` адресом, с
   которого пришло соединение, и добавляют ключ. Для Caddy задайте `FOXAUTH_PROXY_KEY` в окружении, где работает
   Caddy. Для nginx вставьте ключ туда, где в конфигурации написано `<FOXAUTH_PROXY_KEY>`.
3. Запустите проверку со страницы. Она отправляет через прокси поддельный адрес. Шаг не должен стать красным.

Условие по сети нельзя сохранить, пока не пришла проверка с ключом и публичным адресом. Поэтому одно сохранение не
может запереть всех.

### Чему верит проект {#believed}

- Ровно одному адресу, записанному обычным образом. Два адреса, порт, скобки или необычная запись делают адрес
  неизвестным.
- Неизвестный адрес не проходит ни одно условие по сети: ни «только из», ни «не из».
- Частный адрес, например балансировщика или сети контейнеров, для «не из» считается неизвестным. Страница Connect
  говорит, когда прокси присылает такой адрес.
- CDN перед прокси не поддерживается, кроме Cloudflare, когда прокси принимает соединения только с адресов
  Cloudflare.
- Адрес только сравнивается с вашими диапазонами. Он не пишется в журнал и не хранится.

VPN или резидентный прокси всё равно могут обойти список диапазонов. Условие по сети замедляет злоумышленника, но не
останавливает.

Для API адрес принадлежит машине, которая его вызывает. Ассистенты, работающие в облаке, вызывают API из своего
облака, а не из сети человека.

## When: часы работы {#when}

Выберите дни и часы с шагом 15 минут и часовой пояс, в котором их читать. Пояс задаётся один раз для приложения или
API. Часы, которые кончаются раньше, чем начинаются, переходят через полночь: «пт 22:00–06:00» означает ночь с
пятницы на субботу.

Человек, пришедший вне часов, видит, когда приложение откроется снова, в его часовом поясе.

## Attribute {#attribute}

Выберите атрибут и его значения. Это поля, которые задаёт человеку администратор или каталог: отдел, подразделение,
организация, центр затрат, табельный номер, должность или claim, заданный администратором. Claims от внешнего
сервиса входа, например имя или фото, выбрать нельзя: человек может их изменить.

Консоль показывает, сколько людей в проекте подходят. Условие, которому не подходит никто, сохранить нельзя.

## Ask to sign in again {#fresh}

Выберите 15 минут, час, 8 часов, сутки или своё значение от 5 минут. Когда вход человека старше, браузер отправляют
войти снова, и страница входа объясняет зачем. Запрос, который не открывает страницу, получает `401`.

- Страницы, которые подгружают данные в фоне, например дашборды, перестают работать, пока человек не обновит
  страницу. Ставьте условие на пути администратора, а не на всё приложение.
- Кто настроил приложение-аутентификатор, при повторном входе вводит и код.
- Человека, который входит через внешний сервис, попросят войти там снова. Насколько свежий тот вход, решает сервис.

### С кодом из приложения-аутентификатора {#with-code}

Отметьте **with a code from an authenticator app** под условием. Тогда путь откроет только вход, в котором человек ввёл
код и который не старше выбранного времени, самое большее суток. Правило читается как «signed in with a code within
15 min».

- Перед сохранением консоль показывает, у скольких людей, которым открыт путь, нет приложения-аутентификатора и сколько
  входят только через провайдера. Вы подтверждаете с этими числами. Включить это может только тот, кто управляет
  людьми проекта.
- Человек с кодом входит снова с паролем и кодом, даже если уже вводил код в тот же день.
- Человек без кода видит страницу с адресом вашего приложения. Если проект разрешает настроить код самому, человек
  настраивает его там же и попадает на открытую страницу в том же входе. Иначе страница просит обратиться к вам.
- Человеку, который входит через провайдера, объясняют, что так эту страницу не открыть.
- Если вернуться, не войдя, откроется страница о том, что этой странице нужен код. Тот же вход она заново не начинает.
- В **Check access** консоли есть отметка, входил ли человек с кодом.

## Группы и атрибуты для API {#api}

Выберите **Access…** в строке API. Первый раздел, **Who can call it**, содержит условия API. Они действуют до таблицы
инструментов.

Условию о человеке нужен токен, за которым стоит человек. Эти токены таким не являются, и им отказывают:

- токен, который приложение получило для себя, без человека;
- токен приложения, которое даёт людям разные идентификаторы в каждом приложении (pairwise);
- самодостаточный токен, выданный до этого выпуска: в нём не сказано, когда человек вошёл.

При сохранении консоль называет приложения, токенам которых будут отказывать. Заблокированному или отключённому
человеку отказывают сразу. Человеку, которого исключили из группы, отказывают в течение минуты.

## Проверьте перед сохранением {#check}

**Check access** на вкладке Access приложения принимает адрес в приложении, человека, сетевой адрес, момент и время с
момента входа. Он показывает все условия в том порядке, в котором их проверяет проект, с отметками ✓, ✗ или ?. Поле,
которое вы не заполнили, даёт «?».

Изменение, которое пускает больше людей, сначала спрашивает подтверждение и перечисляет, что ослабляется, путь за
путём. Изменение, которое только сужает доступ, сохраняется сразу. Сама консоль FoxAuth никогда не стоит за этими
условиями, поэтому правило не может запереть вас вне её.

## Обновление и откат {#rollback}

Первый выпуск с условиями помечает базу так, что более старый выпуск отказывается с ней запускаться. Старый выпуск не
смог бы соблюдать условия, поэтому работать он не должен. Первый выпуск с кодом у прокси помечает базу ещё раз по той
же причине. Откатиться ниже этого выпуска нельзя. Во время поэтапного
обновления старый процесс, который ещё работает, отвечает ошибкой для приложения или API с условиями, пока его не
заменят. Запрос он не пропускает никогда.
