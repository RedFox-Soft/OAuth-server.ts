手里有泄露密码列表的人，会从一个地址拿它同时尝试你的许多账户。登录节流按每个账户分别统计错误密码，所以一个地址如果对每个账户只试几次，节流拦不住它。本页说明项目如何拒绝已知在做这种事的地址的密码登录。

## 列表里有什么 {#list}

FoxTrust 是接收 FoxAuth 攻击报告的地址信誉服务。它发布一份列表，其中是它在过去 7 天里发现猜测密码的地址。列表每小时重新生成并签名。

- 目前列表中约有 3,000 个地址，大部分来自第三方来源。
- FoxTrust 从不只凭一台服务器的报告就把地址列入列表。
- IPv4 条目是一个地址。IPv6 条目是一个 /64 网络，覆盖该网络中的所有地址。

共享的列表里会有共享的地址：移动运营商的、办公室的、公共 Wi-Fi 的。因此每个项目先统计，只有自己的数字表明可行时才拒绝。

## FoxTrust 会知道什么 {#privacy}

关于谁在登录，它什么都不知道。你的服务器下载列表，并在本地用它核对每次登录。下载时，FoxTrust 只收到名称“FoxAuth”，以及在开启使用情况报告期间的 FoxAuth 版本。不会发送你的服务器名称、任何人的地址或任何账户。

被拒绝者的地址不会被写到任何地方：日志、事件、错误记录、审计记录和计数器里都没有。只有这个人自己在页面上能看到它。

## 开启列表 {#turn-on}

超级管理员打开 **Settings → Integrations**，在 **Attack reporting** 下开启 **Use FoxTrust's list of known password-guessing addresses**。它默认是关闭的。

这个开关需要先开启 **Report attacking addresses to FoxTrust**，因为列表是根据各服务器报告的内容生成的。之后如果关闭攻击报告，控制台会先请求确认，并说明有多少项目正在用列表计数或拒绝。确认后，这些项目不再拒绝任何人。

此后，每个服务器进程会：

1. 每小时下载一次列表，时间在 FoxTrust 重新生成列表后不久；开关打开后一分钟内也会下载一次；
2. 用内置在 FoxAuth 中的密钥验证签名，并拒绝比已持有的列表更旧或已过期的列表；
3. 一份列表最多使用到 FoxTrust 生成它之后的 3 小时。

开关下方的卡片显示列表的生成时间、其中有多少地址、有效期到何时，以及最近一次被拒绝的下载及其原因。

## 用 Count only 来做决定 {#count}

每个项目在 **Sign-in** 标签页的 **Password guessing from known addresses** 卡片中选择：

| 模式                        | 会发生什么                                                      |
| --------------------------- | --------------------------------------------------------------- |
| **Nothing**                 | 来自列表中地址的登录既不统计，也不拒绝。                        |
| **Count only**              | 开启列表后的默认模式。对任何人都没有变化。项目只统计。          |
| **Refuse password sign-in** | 列表中的地址如果不断输错密码，就会被拒绝，详见[下文](#refuse)。 |

卡片显示过去 7 天的三个数字：

- **Password sign-ins from listed addresses**：来自列表中地址的密码登录；
- **Of those, with the right password**：其中密码正确的次数；
- **Refused because of the list**：因列表而拒绝的次数。

先让项目在 Count only 下运行一段时间。如果来自列表中地址的登录有很多密码是正确的，说明你自己的用户和攻击者共用地址，例如在办公室或移动运营商的地址后面。在拒绝之前，先按[下文](#exempt)把这些网络加入例外。如果几乎没有正确的密码，拒绝就是安全的。

## Refuse password sign-in 做什么 {#refuse}

选择 **Refuse password sign-in** 时，控制台会再次显示项目的数字并请求确认。之后：

- 列表中的地址如果在过去 48 小时内被发现猜测密码，并且在一小时内在本服务器上输错 3 次密码，就会被拒绝。
- FoxTrust 通过独立来源确认的地址会立即被拒绝，不需要那 3 次失败。
- 只要该地址继续尝试，就一直被拒绝。一小时内没有尝试后，它又有 3 次机会。
- 使用列表中地址的人如果第一次就输入正确密码，会和以前一样登录。
- 被拒绝的尝试根本不会被检查：不比对密码，也不查找账户。它不计入该账户自己的登录节流，因此攻击者无法用这种方式把账户所有者锁在外面。

这 3 次失败按服务器统计，而不是按项目统计：在一个项目中猜测密码的地址，可能被另一个选择了拒绝的项目拒绝。如果服务器有多个进程，每个进程各自统计。

只影响密码登录。通过身份提供商登录、重置密码、注册以及令牌端点都不受影响。管理员项目不提供 **Refuse password sign-in**，因为它可能把所有管理员挡在控制台之外。

## 被拒绝的人会看到什么 {#refused-page}

密码表单会被一段简短的说明代替，使用此人的语言（英语、俄语或中文）：

1. **此网络暂时无法使用密码登录。**
2. 发生了什么：此网络的地址最近被用于猜测密码。
3. 现在可以怎么做：换一个网络再试，例如用移动数据代替 Wi-Fi，或使用本页上的其他登录方式。项目的身份提供商按钮仍然保留。
4. 一行要发给服务管理人员的文字，其中有此人自己的地址和 UTC 时间：

   ```text
   listed-address · 203.0.113.7 · 2026-11-09 19:58 UTC
   ```

5. 最后是一个链接：**请 FoxTrust 复核此地址**。

无论输入的是哪个 email，也无论账户是否存在，这个页面都一样。

## 帮助被拒绝的人 {#help}

有人把这行文字发给你时，在项目的 **Sign-in** 标签页中，把其中的地址添加到 **Never check these networks**。此人就能立即重新登录。地址从不记录在任何地方，所以只能从这行文字里得到它。

## Never check these networks {#exempt}

项目可以列出永远不与列表核对的地址或范围，例如办公室或 VPN 的出口地址。每一项都可以设置结束日期，过了这一天，列表会再次对它生效。对例外中的地址不做任何统计。

- 可以写一个地址，例如 `203.0.113.7`，或一个范围，例如 `198.51.100.0/24`。IPv6 的写法相同。
- **Your address now** 会填入你当前使用的地址，这样一步就能把自己的网络设为例外。
- 一个项目最多有 100 个例外。

## 地址被误列 {#dispute}

如果某个地址被误列，请在 FoxTrust 的[申诉页面](https://foxtrust.dev/dispute)请它复核。拒绝页面上的链接也指向那里。在该地址被移出列表之前，按[上文](#exempt)把这个网络设为例外。

## 列表过期时 {#stale}

如果没有列表、列表超过 3 小时，或者列表的格式是这个 FoxAuth 版本无法读取的，就不会拒绝任何人。每个使用列表的项目都会在 Sign-in 标签页上说明这一点，例如：“The list is out of date, so nobody is refused because of it.” 当 FoxTrust 几个小时无法访问时就会这样。下一份通过签名验证的列表到达后，保护会恢复。

<Aside type="note">
	如果服务器的调用方地址配置错误，它会把每个人都看成自己代理的地址。受信任代理的地址永远不会与列表核对，因此这样的服务器不会拒绝任何人，而不是拒绝所有人。攻击报告卡片会对此给出警告。
</Aside>

## 给 AI 代理 {#agent}

连接到管理 MCP 端点的代理可以通过控制台自己的路由做同样的事，并记入同一份审计记录：`attacker_list_status_get` 读取列表状态，`project_password_guessing_get` 读取项目的模式、例外和数字，`project_update` 加上 `passwordGuessing` 字段可以修改它们。开启列表本身是服务器设置 `attackerList.enabled`。
